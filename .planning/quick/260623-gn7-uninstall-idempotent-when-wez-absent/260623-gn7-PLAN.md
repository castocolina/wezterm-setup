<objective>
Make `make uninstall` idempotent. `tools/uninstall.sh` currently `err()`s and `exit 1`s when the
`wez` binary is not found (lines 37-41). Because `wez` self-deletes as the LAST step of its own
uninstall (D-01: the glue delegates all removal to the binary), a re-run — or a `make uninstall install`
from a clean / half-installed state — hits the not-found `else` branch and aborts with a non-zero exit
BEFORE `install` runs.

Fix: in the not-found `else` branch only, replace the `err()` + `exit 1` with a `log()` warning and
`exit 0` — "already uninstalled; nothing to remove". The glue stays decision-free (D-01): NO `rm`, NO
path-branching over components, NO inspecting config paths. `set -euo pipefail` stays intact and the
script stays bash-3.2-safe (stock macOS bash).

Purpose: unblock `make uninstall install` from a clean state and make repeated `make uninstall` safe.
Output: a RED regression test, then the GREEN one-branch fix.
</objective>

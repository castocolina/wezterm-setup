## Resolution
<!-- OVERWRITE as understanding evolves -->

root_cause: (1, confirmed) cli/commands/scene.lua sends the per-pane setup escape sequence via `wezterm cli send-text --no-paste` synchronously right after pane creation, with no wait for the pane's shell to reach an interactive prompt. (2, confirmed and FIXED in attempt 2) attempt 1's readiness heuristic (`wait_for_pane_ready`'s "two consecutive identical non-blank samples") was itself unsound: it infers an internal shell state (readline is live and reading stdin) from an external signal it does not control (screen silence), which is ambiguous for any multi-burst startup (e.g. a library-load warning, then a pause, then the MOTD banner, then a pause, then the prompt) -- the poll can land in an inter-burst gap and false-positive as "ready". (3, separate/independent issue, not a scene.lua bug -- documented for the user, not fixed in source) the user's interactively-invoked `wez` on PATH (`~/.local/bin/wez`) is a compiled release binary from an earlier install, NOT the dev source launcher -- it never reflects uncommitted source fixes at all; the user must rebuild/reinstall (or invoke `./dist/wez` directly) to pick up this fix.
fix: attempt 1 (`wait_for_pane_ready`, bounded 2-identical-samples silence poll) was INSUFFICIENT and has been REPLACED (not layered on top of) by attempt 2: an active echo-marker probe. `wait_for_pane_ready` now sends `echo <unique marker>\n` via send-text and polls `wezterm cli get-text` for a screen line that, once trimmed, is EXACTLY the marker -- proof the shell actually EXECUTED the probe (its own stdout), not merely that the pty echoed the typed `echo <marker>` command text back (which happens immediately regardless of shell readiness -- that immediate echo IS the literal-text leak this bug is about, so raw-text appearance can never be used as a readiness signal). The probe is resent every 5 of the 30 bounded 0.1s poll attempts (3s total cap, same fail-open-after-cap behavior as before) to guard against the probe itself being queued-but-never-delivered by whatever mechanism can also swallow the real payload. This is immune to the shape/count/timing of the shell's own startup chatter -- it never inspects the shell's own output, only its own probe's round trip.

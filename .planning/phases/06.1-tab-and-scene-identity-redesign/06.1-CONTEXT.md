# Phase 06.1: Tab and Scene Identity Redesign - Context

**Gathered:** 2026-06-15
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 6.1 is a **cleanup + extension** phase — the last redesign before the macOS parity pass
(Phase 7), so macOS verifies the redesigned behavior. It delivers:

1. **Decouple tab COLOR from tab TITLE everywhere** — drop the legacy `"<color>:<title>"`
   set-tab-title encoding (a pre-roadmap scripting shortcut). Tab color becomes the
   `WEZTERM_TAB_COLOR` user var emitted on the tab's panes (same two-user-var model panes already
   use); tab title becomes pure text via `set-tab-title`. `format-tab-title` reads color by scanning
   the tab's panes. Applies to BOTH scenes AND standalone `wez tab` / `wez pane`. Drop
   `parse_stored` / `merge_title` + the encoding (parse-and-warn once for migration).
2. **Scene TOML schema redesign** — tab attributes as top-level keys; panes as `[[pane]]` arrays;
   scope enforced by table grammar, same attribute names + semantics.
3. **New recipe/CLI fields `cwd` / `focus` / `size`** (resolution grammar already locked).
4. **Color model accepts alpha** — accept `#RRGGBBAA` / `rgba()` (stop stripping the 8th digit);
   named palette stays the DEFAULT; alpha only renders with window transparency (D-18 caveat).
5. **Migrate the prototype `wezterm.lua`** — remove the inline `format-tab-title` handler +
   duplicate keybindings that shadow the managed block (root cause of the `cyan:` / no-color /
   no-cwd bug); keep genuine personal settings; installer writes a backup.
6. **`wez doctor` shadow-detection** — detect a user-defined `format-tab-title` handler or
   keybindings shadowing wezterm-setup, so this bug class surfaces loudly.
7. **Arrange actions** — bind `RotatePanes` (Clockwise / CounterClockwise), keep the zoom toggle;
   frame scenes as launchable layout presets ("Arrange" = live, "Scenes" = presets). NO kitty-style
   layout engine.
8. **Embrace the search overlay** — keep WezTerm's `Ctrl+Shift+F`; document `Ctrl+R`
   (CopyMode `CycleMatchType`) to cycle case-sensitive / case-insensitive / regex. Relaxes the prior
   "no less-style search overlays" philosophy rule.
9. **Refresh `ai` + `dev` seed scenes** — give them real commands + per-pane/tab colors (like the
   docker scene).

**No new requirement IDs** — refines PANE-* / SCEN-* / TAB-* behavior and **supersedes the
"tab color stored in tab-title prefix" decision** (`tab-title-format.md`).

**macOS:** Linux-first, designed cross-platform (D-18); verified in the Phase 7 Mac pass.
</domain>

<decisions>
## Implementation Decisions

> **Scope was pre-locked with the maintainer in ROADMAP.md.** The decisions below resolve the
> remaining open HOW questions from discussion; the locked roadmap scope (items 1–9 above) is the
> binding contract and is NOT re-litigated here.

### Cross-cutting — single shared identity path (ENTROPY REDUCTION — maintainer directive)
- **D-01 (INVARIANT):** **One well-designed, reused implementation** for color / title / cwd
  resolution + application, shared across **scene launch, scene new, standalone `wez pane`, and
  `wez tab`**. No parallel copies, no divergent edge handling. The planner MUST run
  **`/reducing-entropy`** during planning to consolidate the color normalizer, title/icon resolver,
  cwd resolver, and the pane-spawn (color+title+cwd emit) path into shared `cli/lib/` modules
  consumed by every entry point. This is the headline maintainer constraint for the phase. The
  existing pure-core / IO-shell split (Phase 4) is the structural template.

### Tab color resolution (decouple, item 1)
- **D-02:** **Active pane wins.** When panes within one tab carry different `WEZTERM_TAB_COLOR`
  values, the tab title bar uses the color of the **currently focused pane** (`format-tab-title`
  reads `tab.active_pane`). Tab color may change as focus moves — accepted/intended. (Title
  resolution keeps the existing pane-var > tab-text precedence; only the color carrier changes from
  the prefix encoding to the user var.)
- **D-03:** **Mechanism is OSC 1337 `SetUserVar` written to the pane TTY** — the same channel pane
  identity already uses. `wez tab color` emits `WEZTERM_TAB_COLOR` via OSC to the tab's pane(s). This
  is locked and known; the only work is our implementation. Do NOT treat it as an open research
  question.
- **D-04:** **Parse-and-warn migration** — the legacy `"<color>:<title>"` set-tab-title encoding is
  read once for migration with a warning, then dropped. `parse_stored` / `merge_title` are removed
  from the steady-state path.

### Recipe / CLI new fields (item 3)
- **D-05:** **`focus` = per-pane boolean `focus = true`** on a `[[pane]]` (CLI: a `--pane` segment
  `focus=true`). First pane marked wins; **validate-before-emit errors on >1** focused pane. Same
  per-pane shape as `color` / `title`.
- **D-06:** **`size` = integer percent `1..100`** on a `[[pane]]` (e.g. `size = 30` = 30% at its
  split step). Panes that omit `size` share the remainder equally (today's behavior). Planner maps
  the percent onto WezTerm's `SplitPane` size (`Percent`).
- **D-07:** **`cwd` defaults to the launch dir** — a pane that omits `cwd` opens in the directory
  `wez scene launch` / `wez scene new` was invoked from (inherit). Consistent with the locked cwd
  grammar where `.` = launch dir. A pane may override via the locked grammar
  (literal / `~` / `$ENV` / relative; NO `$(...)`).
- **D-08 (REQUIREMENT — clean pane):** cwd MUST be applied at **pane spawn time** via WezTerm's
  native spawn `cwd` (`SpawnCommandInNewTab` / `SplitPane` `cwd`), so the pane opens **directly** in
  the target directory with **NO visible `cd <path>` line** in the scrollback. The current
  spawn-then-`cd` approach leaves clutter and is the bug to fix. This folds into the D-01 shared
  spawn path and the Phase 4 clean-pane decision (D-09).

### Color model alpha (item 4)
- **D-09:** Accept **`#RRGGBBAA`** (stop stripping the 8th hex digit in the normalizers
  `tab.lua:strip_alpha` / `pane.lua` + the scene/format-tab-title resolvers). Named palette stays
  the DEFAULT and documented surface. `rgba()` CSS-function parsing is **Claude's discretion** —
  add it if cheap within the shared normalizer; `#RRGGBBAA` is the must-have. Document that alpha
  only renders with window transparency (cross-platform caveat, D-18).

### Migration + doctor (items 5, 6)
- **D-10:** **Migration is best-effort detect + clear instructions** — this is a solo
  daily-driver setup, not a mass product; a clean reinstall (or `wez uninstall`, see Deferred) is
  always an acceptable reset. `wez doctor` detects the shadowing constructs and tells the user
  exactly what to remove; a fragile auto-rewrite of the user's personal `wezterm.lua` is NOT
  required. (If an opt-in backed-up `--fix` is cheap the planner may add it, but the bar is
  detect + instruct + installer backup.)
- **D-11:** **doctor shadow-detection is a CORE GATE** (non-zero exit) — alongside binary-on-PATH /
  sentinel / config-dofiles / backup gates, not an advisory probe. A detected shadowing
  `format-tab-title` handler or duplicate-shadowing keybinding fails `wez doctor` loudly.

### Arrange keys (item 7)
- **D-12:** **`Alt+Shift+R` = RotatePanes Clockwise**, **`Alt+Shift+E` = RotatePanes
  CounterClockwise** — fits the existing `Alt+Shift+{H,V,X,Z,arrows}` pane family ("R for Rotate",
  E sits left of R). Keep the existing `Alt+Shift+Z` zoom toggle. Add
  `DisableDefaultAssignment` entries for any replaced defaults (truthful `wez keys`).

### Seed scene refresh (item 9)
- **D-13 (`dev` scene):** `layout = "tall:mirrored"`, **green** tab color; **3 panes** —
  editor (run `$EDITOR`, green), working shell (teal), git pane (`git status` / lazygit-style,
  yellow). cwd inherits the launch repo (D-07/D-08). Must round-trip through the loader to the same
  result as the equivalent `scene new` (SCEN-04 equivalence).
- **D-14 (`ai` scene):** `layout = "tall"`, **purple** tab color; **2 panes** — AI CLI
  (`claude`, purple) + working shell (teal). cwd inherits launch dir.
- **D-15:** Seed `.toml` content is delivered copy-if-absent by the existing seeder (Phase 5 D-07);
  refreshing the in-repo `scenes/ai.toml` + `scenes/dev.toml` updates only what a fresh install
  seeds — it does NOT overwrite a user's already-edited recipe.

### Claude's Discretion
- `rgba()` CSS-function parsing (D-09) — add if cheap; `#RRGGBBAA` is the floor.
- Exact `[[pane]]` vs `[[panes]]` key (ROADMAP says `[[pane]]`; keep migration alias for the current
  `panes` + top-level `color`/`title` during migration).
- The precise shared-module decomposition produced by `/reducing-entropy` (D-01) — which helpers land
  in which `cli/lib/` module — under the "one shared path, no duplication" invariant.
- The exact `git` pane command in `dev` (`git status` vs lazygit-style) and the exact editor
  invocation, per what's available cross-platform.
- Opt-in `wez ... --fix` for migration (D-10) if cheap.
- Migration warn surface/lifetime for the legacy encoding (D-04).

### Established Patterns
- **Pure-core / IO-shell split** — the structural template for the D-01 consolidation.
- **Validate-before-emit** — applies to the new `focus`>1 error (D-05) and color/cwd validation.
- **Spec-driven completion / `wez keys` (D-16)** — register all new surface in `cli/spec.lua`.
- **Config AUGMENT (D-17)** — keybinding + formatter changes merge via the managed block.
- **Decision-free installer (D-01 foundation)** — seed refresh stays in the Lua seeder (D-15).

### Integration Points
- **Tab color write:** `wez tab color` → OSC 1337 `SetUserVar WEZTERM_TAB_COLOR` to the tab's
  pane(s) (D-03); title via `set-tab-title` (pure text).
- **Tab color render:** `format-tab-title` reads the **active pane's** `WEZTERM_TAB_COLOR` (D-02).
- **Scene spawn:** spawn each pane with native `cwd` (D-08) → OSC color/title → focus the
  `focus=true` pane (D-05) → apply `size` percent splits (D-06) — all through the D-01 shared path.
- **doctor:** new core gate greps the user's `wezterm.lua` for a `format-tab-title` handler /
  shadowing keybindings (D-11).

### Hypothesis policy
Behavior changes (OSC tab-color emit + active-pane render D-02/D-03, clean-pane spawn cwd D-08,
RotatePanes keys D-12) get a manual repro against a live WezTerm session (`wez doctor` output or
recorded repro) before integration — per CLAUDE.md "verify before declaring done".

<specifics>
## Specific Ideas

- **"Use `/reducing-entropy` during planning"** — the maintainer's explicit directive (D-01):
  well-designed, reused code for colors/title and all the edges across scene launches AND individual
  pane/tab spawns. This is the defining constraint of the phase.
- **"El pane debería quedar limpio"** — the clean-pane cwd requirement (D-08): applying cwd must not
  leave a visible `cd <ruta>` line; spawn directly in the target directory. Current behavior runs
  `cd` and leaves clutter — that's the bug to fix.
- **"This isn't a mass-market product"** — relaxed migration stance (D-10): best-effort detect +
  instruct; a clean reinstall is an acceptable reset.
- **"Active pane wins"** — the tab reflects what you're currently looking at (D-02).
</specifics>

  the binary was downloaded (not the repo). Raised during migration discussion; pairs naturally with
  the migration story (D-10) but is a **new capability** → roadmap backlog, not 6.1 scope. Worth
  adding as a small companion to `wez update` / the installer.
- **`rgba()` CSS-function color parsing** — not deferred outright; it's Claude's discretion this
  phase (D-09). `#RRGGBBAA` is the committed minimum.
- **Opt-in migration `--fix` auto-rewrite** — allowed but not required this phase (D-10).
- **kitty-style layout engine** — explicitly rejected by the roadmap (Arrange = RotatePanes presets,
  not a layout engine). Not deferred — out of scope by design.

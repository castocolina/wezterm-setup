<objective>
Ship the INST-07 CONSUME side: the ergonomic one-line remote installer `tools/install.sh` (the
`curl -fsSL <raw-url> | bash` + `wget -qO- | bash` entry point) and the rewritten README install
section. This is the user-facing front door for everything the supply side (Plan 02 `download_release()`
+ the `wez-<os>-<arch>` asset contract, Plan 03 CI) produces.

`install.sh` is pure D-01 glue — it makes ZERO install decisions. It only: (1) wraps its whole body in
`main()` invoked on the literal last line so a truncated `curl` stream can never execute a half-command
(P6-D05 / RESEARCH Pattern 1); (2) creates a `mktemp -d` guarded by `trap '... rm -rf' EXIT` for
nothing-left-behind cleanup (P6-D02 SC#3 / Pattern 3); (3) fetches the repo via the GitHub **codeload
tar.gz** endpoint piped into `tar --strip-components=1` (no `git` dependency — Claude's-discretion
resolved to tarball per RESEARCH; Pattern 5); (4) hands off to the EXISTING `tools/setup.sh` with
`WEZ_REMOTE_BOOTSTRAP=1` so setup bootstraps/reuses WezTerm (never touching a system install, P6-D09),
downloads the `wez-<os>-<arch>` release binary (Plan 02's path), places assets, and finishes with
`wez doctor` pass/fail. The WezTerm refresh half of that hand-off now flows through 06-06's nightly-default
+ update-in-place path (setup.sh STEP 2 -> bootstrap-wezterm.sh): the default target is the rolling
`nightly`, a behind-the-latest user-path install is updated in place, and a system install is left intact —
all owned by 06-06; install.sh adds NO version/target/update code (still pure glue, no new code here for
that). Interactive prompts stay live under the pipe by redirecting the child's stdin from `/dev/tty`
(P6-D04 / Pattern 2); a genuinely headless run (no `/dev/tty`) keeps the D-03 non-zero abort, with flags
passable via `bash -s -- --force|--restore|--skip`.

The README rewrite (P6-D06, authored to the `crafting-effective-readmes` skill structure) replaces the
BROKEN `…/tools/setup.sh | sh` one-liner with the real castocolina `curl`/`wget`/`bash <(curl …)` forms,
post-install/config steps, and the inspect-before-run + pin-to-tag trust model (P6-D05).

Purpose: Without this entry script + README, the published assets have no user-facing installer; the
current README one-liner is non-working (placeholder `you/` owner, `setup.sh` assumes a checkout, `| sh`).
Output: `tools/install.sh` (NEW), a `bash -n` shell-syntax gate in `tools/run-tests.sh`, an
`install_sh_test.lua` text/contract test (incl. a deterministic headless-abort assertion), and the
rewritten README install section.

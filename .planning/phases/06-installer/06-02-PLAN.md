<objective>
Build the INST-08 SUPPLY side that the remote installer (Plan 04) and `wez update` (Plan 05) consume:
repoint the dormant `WEZ_REMOTE_BOOTSTRAP=1` release-download path in `tools/build.sh` to the real
`castocolina` URL, adopt the per-asset `<asset>.sha256` contract ratified in Plan 01, make the checksum
verify portable (macOS has no `sha256sum`), and add the local `make build` / `make publish` first-class
capability (P6-D08) so a maintainer on Linux OR macOS can cut that platform's asset with the SAME
asset-naming contract CI uses.

This is ~all WIRING of existing, tested glue (RESEARCH: do not re-implement download/verify). The new
file is one thin `tools/publish.sh`; the rest are minimal edits to `build.sh` + `Makefile` + one Lua
contract test.

Purpose: Without a published, correctly-named, checksum-verifiable asset, the launcher has nothing to
download — this plan makes `wez-<os>-<arch>` exist and be verifiable.
Output: Repointed+portable `build.sh`, new `tools/publish.sh`, `make build`/`make publish` targets, and
a `publish_test.lua` pinning the asset-name contract.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| maintainer host → GitHub Releases (`gh release upload`) | Authenticated publish; the asset + checksum cross from local build into the public download surface |
| installer host → GitHub Releases (`download_release()`) | Untrusted download of `wez-<os>-<arch>` + `<asset>.sha256` over HTTPS, verified before exec |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Tampering | downloaded `wez` binary | mitigate | `download_release()` verifies `<asset>.sha256` (single-line parse) BEFORE `chmod +x`; mismatch or missing checksum aborts non-zero (T-01-01 preserved across the contract change) |
| T-06-02-02 | Tampering | wrong-arch / no-asset case | mitigate | asset name is built from the closed `platform_os`/`platform_arch` set (never raw input); a missing asset 404s the fetch → non-zero, never a silent wrong-binary fallback (P6-D07) |
| T-06-02-03 | Spoofing | macOS arm64 binary won't load unsigned | mitigate | `publish.sh` ad-hoc-codesigns (`codesign --force --sign -`) on macOS+aarch64 (Pattern 7); Gatekeeper/quarantine runtime check is Phase 7 |
| T-06-02-04 | Information Disclosure | `gh` auth token | accept | `gh` manages its own credential store; publish runs only on the maintainer's authenticated host — no token handled by our scripts |
| T-06-02-SC | Tampering | npm/pip/cargo installs | mitigate | No language-registry installs in this plan. Build/publish-side `luastatic` (LuaRocks) is the project's locked build tool (D-02), `[ASSUMED]`, gated by a real install on the runner (Plan 03 / CI); slopcheck does not cover LuaRocks. No `[SLOP]`/`[SUS]` packages. |
</threat_model>

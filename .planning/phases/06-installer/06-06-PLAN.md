<objective>
Close the three plan-checker BLOCKERS that the prior plan set left open in `tools/bootstrap-wezterm.sh`,
delivering the P6-D09 WezTerm version policy that BOTH the one-liner (Plan 04 → `setup.sh` STEP 2) and
`wez update` (Plan 05) depend on. All three are surgical changes to the existing detection-first bootstrap
glue (D-01: detection + fetch + place, zero policy beyond which install PATH to take); none re-implements
fetch/extract — the update path reuses the proven STEP-3 mechanism.

1. **BLOCKER 1 — update-in-place branch (ROADMAP SC#8 / P6-D09):** `detect_and_reuse()` today compares the
   installed datestamp ONLY to the fixed `WEZTERM_MIN_RELEASE` and, if `have ≥ min`, reuses untouched and
   returns 0 — even when a project user-path install is BEHIND the latest nightly. Add a "want = latest
   nightly datestamp" target (the query ratified in 06-01-SUMMARY.md, with its documented graceful-degrade
   fallback) and an UPDATE-IN-PLACE branch: when the active install is the project USER-PATH install
   (Blocker 3 predicate) AND its datestamp `<` the latest-nightly want → fetch+extract+swap the newer
   nightly by REUSING the existing `install_linux()` STEP-3 fetch/extract/symlink mechanism (do NOT
   re-implement). When the install already meets the want (`≥`) → reuse untouched (no-op).

2. **BLOCKER 2 — nightly default (P6-D09):** `WEZTERM_MIN_RELEASE` defaults to `WEZTERM_PINNED_RELEASE`,
   and `select_release()` under no-TTY prints the pinned release — so the installer targets the PINNED
   dated release by default, contradicting P6-D09 (nightly is the default target, including the
   non-interactive pipe path; pinned stays an explicit opt-in for reproducibility). Add a
   `WEZTERM_TARGET="${WEZTERM_TARGET:-nightly}"` seam consumed by `select_release()` and the update path so
   the default target is the rolling `nightly`; preserve `WEZTERM_PINNED_RELEASE` as the opt-in
   (`WEZTERM_TARGET=pinned`, or an explicit dated tag). Do NOT break the existing detection-first
   non-destructive reuse of a system install (D-07).

3. **BLOCKER 3 — real install-kind predicate (the P6-D09 safety gate):** the "never touch a system install"
   constraint currently rests on `detect_and_reuse:83`'s LOG-ONLY outside-`BIN_DIR` check, reachable only
   inside the reuse-success path and returning no value. Factor a REAL, reusable predicate
   `wezterm_install_is_user_path()` returning true iff the resolved `wezterm` binary is under `${BIN_DIR}`
   (the project user-path), false for `/usr/bin/...` (the verified apt `wezterm-nightly` case), that BOTH
   the bootstrap update-in-place branch AND `cli/commands/update.lua` (Plan 05) can call. The
   update-in-place and any swap are GATED on this predicate = user-path; a system install is left intact
   with an informational message (offer to place a user-path copy that wins on PATH, per P6-D09).

Purpose: Without this plan, the one-liner and `wez update` cannot deliver SC#8 (refresh WezTerm when a
newer nightly exists), default to the wrong target (pinned, not nightly), and rest the system-install
safety on a log line rather than a checkable predicate.
Output: `tools/bootstrap-wezterm.sh` (MODIFIED — `WEZTERM_TARGET` nightly default, latest-nightly want
resolver, update-in-place branch, `wezterm_install_is_user_path()` predicate) and
`tests/cli/bootstrap_update_test.lua` (NEW — TEXT + behavior assertions, the project test convention).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bootstrap → GitHub releases API / asset host (`api.github.com`, `github.com/wez/wezterm`) | Untrusted network response feeding the "is a newer nightly available?" datestamp decision; HTTPS, official `wez/wezterm` host only |
| bootstrap (update-in-place swap) → the on-disk WezTerm binary under `${BIN_DIR}` | A running session's WezTerm being swapped for a newer nightly — must be user-path only, atomic-`ln -sfn`, never a system path |
| bootstrap → a system WezTerm install (`/usr/bin/wezterm`, root-owned apt `wezterm-nightly`) | A privilege boundary that must NEVER be crossed (no sudo, no fetch-over) |

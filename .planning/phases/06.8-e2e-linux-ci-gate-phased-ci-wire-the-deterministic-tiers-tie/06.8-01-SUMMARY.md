# Phase 06.8 Plan 01: E2E Linux CI Gate Summary

**A real `.github/workflows/ci.yml` now gates every push/PR: `make test` -> WezTerm nightly provisioning -> the full deterministic e2e battery (Tier 1 + Tier 2 + Tier 3-registration) -> a dedicated classify script that hard-fails on any unexpected self-skip or missing live-assertion. Getting a genuinely green run surfaced and fixed FOUR real, previously-latent production bugs that only a bare, real CI runner could expose.**

## Accomplishments

- Wrote `.github/workflows/ci.yml` (single `test-and-e2e` job, `ubuntu-latest`, 25min timeout): checkout -> Lua toolchain -> wezterm-gui runtime deps -> `make test` (fail fast, D-04) -> resolve+cache WezTerm nightly (D-01, corrected) -> provision WezTerm -> verify wezterm+mux resolvable (D-02 precondition) -> `make build` -> install wezterm-setup for live show-keys parity -> the e2e battery (D-02 gate, classified) -> upload the e2e log artifact.
- Delegated every non-trivial decision to a dedicated `tools/ci-*.sh` script (D-01 boundary: no decision logic inline in YAML) — cache-key resolution, mux-resolvability verification, and the pass/fail classification of the e2e log.
- Found and fixed FOUR real bugs that only manifested on a genuinely bare Linux CI runner (never reproduced on the maintainer's own already-provisioned dev box):
  1. `wez install-state` / `wez doctor` / `M.backup` all unconditionally assumed a pre-existing `wezterm.lua` — crashed outright on a machine with none at all.
  2. `wezterm-gui` (which `wezterm show-keys` re-execs into) dynamically links against XCB/xkbcommon shared libraries `ubuntu-latest` does not ship by default.
  3. `wez keys --json`'s vendored `require("dkjson")` only resolves via the dev launcher's package.path fallback — the luastatic-bundled release binary preloads it under its derived dotted module name and has no such fallback.
  4. `wez doctor`'s backup-exists core gate had no way to distinguish "nothing pre-existed, so no backup was needed" (bug 1's own fix) from "real content was silently overwritten" — a direct regression introduced by fixing bug 1, caught before it shipped.
- Independently verified the final green run (`34302443163`) by downloading the `e2e-output-log` artifact myself and re-running `tools/ci-classify-e2e-output.sh` against it — never trusted a run's own `conclusion` field alone (ONESHOT-RULES Rule 1).

## Deviations from Plan

### Auto-fixed Issues (found via live CI, not anticipated in planning)

**1. [Bug] `wez install-state` crashed on a target that does not exist at all**
- **Found during:** first live CI run (`34299249049`) on a genuinely bare runner.
- **Fix:** seed `DEFAULT_CONFIG_SKELETON` on ENOENT; treat a missing backup source as no-op success.
- **Commit:** `b2bdf3b`.

**2. [Bug] `wezterm-gui` missing XCB/xkbcommon shared libraries on `ubuntu-latest`**
- **Found during:** second live run (`34300180723`), root-caused via a permanent diagnostic added in `92f05c0` that surfaced the real linker error (`libxcb-image.so.0: cannot open shared object file`) instead of a generic self-skip message.
- **Fix:** new `tools/ci-install-wezterm-runtime-deps.sh`, wired before WezTerm provisioning.
- **Commit:** `053d952`.

**3. [Bug] `wez keys --json` failed inside the luastatic-bundled release binary**
- **Found during:** third live run (`34301496214`), root-caused via diagnostics added in `80ce8db` surfacing `"no module 'dkjson' in luastatic bundle"`.
- **Fix:** try-dotted-then-bare require, matching `cli/spec.lua`'s existing pattern.
- **Commit:** `ef34530`.

**4. [Bug] `wez doctor`'s backup-exists gate regressed by this plan's own bug-1 fix**
- **Found during:** same diagnostic pass as bug 3 (same CI run's log).
- **Fix:** provenance-check exemption comparing the managed-block-stripped config against the known seed skeleton.
- **Commit:** `ef34530`.

None of these four bugs were anticipated in the original plan text — each was discovered ONLY because this phase's goal (a real, bare CI runner exercising the full battery) is precisely the condition that exposes them. This is exactly the value this phase exists to deliver.

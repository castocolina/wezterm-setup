## WezTerm provisioning in the CI runner

| Option | Description | Selected |
|--------|-------------|----------|
| Pinned via `bootstrap-wezterm.sh` (`WEZTERM_TARGET=pinned`) | Reuse the existing installer with a deterministic release, cached across runs | ✓ (Claude's discretion) |
| Rolling nightly (tool's own default) | Track the latest nightly on every run | |

**User's choice:** "You decide."
**Notes:** Claude chose the pinned mechanism because a moving nightly target would make the
E2E gate's pass/fail nondeterministic across runs with no code change of ours — the opposite
of what a CI gate is for. The download/install directory should be cached, keyed on the
pinned release identifier.

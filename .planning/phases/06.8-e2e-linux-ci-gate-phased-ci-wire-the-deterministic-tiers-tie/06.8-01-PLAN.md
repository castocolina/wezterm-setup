<objective>
Wire the deterministic E2E tiers — Tier 1 (subcommands), Tier 2 (scenes, live mux), Tier 3
registration (show-keys chord families) — into a new GitHub Actions workflow on Linux, so they
gate every `push` to `main` and every `pull_request` going forward (PRD Phase 3). WezTerm is
provisioned in the runner via `tools/bootstrap-wezterm.sh WEZTERM_TARGET=pinned` (D-01), cached
across runs; `make test` runs before `make e2e` in the same job (D-04); the e2e run targets the
freshly `make build`-produced `dist/wez`, never the dev launcher (D-05); and the gate treats any
Tier 2/3 self-skip as a hard failure so a "green" run can never be a hollow one (D-02). The
workflow reports pass/fail only — no branch-protection required-status-check wiring (D-05). Tier
3 firing and Tier 4 visuals stay local/best-effort (06.9) and are never touched here.

Purpose: a green e2e battery is only trustworthy going forward if it runs automatically on every
change, not just when a human remembers to run `make e2e` locally — this closes that gap.
Output: `.github/workflows/ci.yml` (new) + a corrected `tests/e2e/README.md` WEZ_BIN example, plus
one real, live-verified GitHub Actions run proving the gate actually works end-to-end.
</objective>

<objective>
Wire the deterministic E2E tiers — Tier 1 (subcommands), Tier 2 (scenes, live mux), Tier 3
registration (show-keys chord families) — into a new GitHub Actions workflow on Linux, so they
gate every `push` to `main` and every `pull_request` going forward (PRD Phase 3). WezTerm is
provisioned in the runner via `tools/bootstrap-wezterm.sh WEZTERM_TARGET=nightly` (D-01, revised
in this replan — the literal `pinned` mechanism was found, via live verification, to reference a
`wez/wezterm` release that has never existed), cached deterministically across runs keyed on the
resolved nightly-asset datestamp; `make test` runs before BOTH WezTerm provisioning and `make e2e`
in the same job (D-04); the e2e run targets the freshly `make build`-produced `dist/wez`, never the
dev launcher (D-05); and a dedicated classification script treats any UNEXPECTED Tier 2/3 self-skip
as a hard failure while correctly tolerating the ONE intentional macOS-only Tier 1 self-skip, so a
"green" run can never be a hollow one (D-02). The workflow reports pass/fail only — no
branch-protection required-status-check wiring (D-05). Tier 3 firing and Tier 4 visuals stay
local/best-effort (06.9) and are never touched here.

This is a `--reviews` mode replan: cross-AI review (OpenCode) found 5 HIGH + 2 MEDIUM defects in
the prior version of this plan, all incorporated below — see `<review_dispositions>`.

Purpose: a green e2e battery is only trustworthy going forward if it runs automatically on every
change, not just when a human remembers to run `make e2e` locally — this closes that gap, honestly
(a gate that cold-fails on its first real run, or that can't tell an expected skip from a real one,
is worse than no gate at all).
Output: `.github/workflows/ci.yml` (new), `tools/ci-classify-e2e-output.sh` (new), a corrected
`tests/e2e/README.md` WEZ_BIN example, plus one real, live-verified GitHub Actions run — correlated
to the exact pushed commit SHA — proving the gate actually works end-to-end.
</objective>

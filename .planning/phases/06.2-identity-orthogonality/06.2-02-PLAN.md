<objective>
Add the icon CLI surface and split the color carriers — the user-facing half of
G-1 (icon as its own attribute) and G-2a (tab color vs pane color split) — across
the standalone wez tab / wez pane entry points, plus their single registration in
cli/spec.lua. Also lands the only migration surface Phase 6.2 ships: the lightweight
legacy icon-in-title parse-and-warn (D-06).

This plan delivers the FULL command path a user runs (D-01: subcommand AND
convenience flag), with CLI round-trip e2e tests that assert the exact OSC 1337
SetUserVar sequence for the correct user var. It OWNS cli/spec.lua for the whole
phase (the recipe/scene plan reads the registered grammar but does not edit it).

LOCKED CROSS-PLAN CONTRACT (W3): the follow-pane opt-in carrier user var is named
**WEZTERM_TAB_FOLLOW_PANE**, payload "1" when ON and unset/empty when OFF. This exact
literal is referenced independently by Plans 02 (emit), 03 (render read), and 04
(scene emit) — it is NOT discovered from a comment one plan writes at runtime, so
Plans 02 and 03 stay parallel in wave 2.

MIGRATION DECISION (D-06, W2): the legacy icon-in-title shortcut gets ONLY a one-time
CLI stderr warn — there is deliberately NO `wez doctor` gate, advisory probe, auto-fix,
or persistent migration tracking. This overrides the ROADMAP §06.2 G-2b "extend wez
doctor if a new shadowing/coupling class emerges" bullet (maintainer, verbatim: "This
is not a massive distributed app, we can remove the legacy behavior and forget about
someone using legacy config"). Recording the decision-NOT-to-build the gate here so the
verifier does not later flag the absent gate as a miss.

Purpose: D-01 (icon subcommand + --icon on title), D-02 (named-or-literal icon via
the shared resolver from Plan 01), D-03 (WEZTERM_TAB_ICON carrier), D-06 (legacy
icon-in-title parse-and-warn, no doctor gate), D-07 (split WEZTERM_TAB_COLOR /
WEZTERM_PANE_COLOR), D-09 (--follow-pane-color opt-in via WEZTERM_TAB_FOLLOW_PANE), D-16.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argv -> OSC 1337 SetUserVar to the pane TTY | user-supplied icon/color/title values cross into terminal escape sequences written to the active pane's TTY |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06.2-03 | Tampering | OSC injection via icon/title value (emit seam in tab.lua/pane.lua) | mitigate | All values go through color.build_osc1337 (cli/lib/color.lua:110-112), which base64-encodes the payload — control bytes (ESC, BEL, ST) in a malicious icon/glyph cannot break out of the SetUserVar frame. No raw-string emit path is added; every new emit (WEZTERM_TAB_ICON, WEZTERM_PANE_COLOR, WEZTERM_TAB_FOLLOW_PANE) reuses build_osc1337. Asserted by the test that the captured OSC equals build_osc1337(var, value). |
| T-06.2-04 | Tampering | color value | mitigate | wez tab/pane color keep the strict color.validate_color gate (validate-before-emit, pane.lua:74-78); the split changes only the varname, not validation. |
| T-06.2-05 | Elevation of Privilege | shell eval of value | mitigate | No value is interpolated into os.execute as code; set-tab-title text is shquote'd (tab.lua:82), OSC values are base64. No $(...) path is introduced (D-08 no-shell-eval invariant). |
| T-06.2-13 | Information disclosure | legacy-icon-name warn echoes the user's title word to stderr | accept | The warn echoes only the user's own leading title word back to their own stderr (no privilege boundary crossed, no secret); it performs no terminal write/OSC and no swap (D-06). Bounded to one line per process by the one-time guard. |
| T-06.2-SC | Tampering | npm/pip/cargo installs | accept | This phase installs NO new packages (pure-Lua, zero-dep); reuses already-vendored argparse/dkjson. No package legitimacy gate needed. |
</threat_model>

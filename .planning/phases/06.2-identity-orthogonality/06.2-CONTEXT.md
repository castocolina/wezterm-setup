# Phase 06.2: Identity Orthogonality - Context

**Gathered:** 2026-06-16
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 6.2 finishes the decoupling Phase 6.1 started. 6.1 separated tab **color**
from tab **title**; 6.2 extends the same orthogonality principle to the two attributes
still coupled — the **icon** (today inferred from the title's first word) and the
**tab-vs-pane color** (today a single shared user var). After 6.2:

1. **Icon is its own attribute (G-1)** — a dedicated `icon`, settable on the CLI and in
   scene recipes, decoupled from `title`. Rendered via a distinct carrier
   (`WEZTERM_TAB_ICON`) composed as `icon + title`, so title text stays literal.
   Revises 6.1's D-03/D-04 (icon-in-title).
2. **Tab color split from pane color (G-2a)** — `WEZTERM_TAB_COLOR` (the tab's own,
   stable color) is split from `WEZTERM_PANE_COLOR` (per-pane accent). An explicit tab
   color ALWAYS wins; the active pane's color is used only when opted in. Revises D-02.
3. **Explicit opt-in "follow the focused pane's color" (G-2b)** — the old auto-adopt
   behavior becomes an opt-in `follow_pane_color` (recipe key + CLI flag), default OFF.
4. **`{cwd}`-in-title auto-fallback** — when a title resolves to empty, auto-fall-back to
   the launch-dir basename so panes/tabs self-label by directory.
5. **Migration** — lightweight CLI parse-and-warn for legacy icon-in-title usage; refresh
   seed scenes to use the explicit `icon` attribute.

**No new requirement IDs** — refines PANE-* / TAB-* / SCEN-* identity behavior and
**supersedes 6.1's D-02 (active-pane-wins) and D-03/D-04 (icon-in-title)**.

**Single shared path (carries forward 6.1 D-01 — INVARIANT):** the new carriers
(`WEZTERM_TAB_ICON`, `WEZTERM_PANE_COLOR`) and the new resolution logic MUST live in the
shared `cli/lib/` modules consumed by every entry point (scene launch/new, standalone
`wez tab` / `wez pane`). No parallel copies. Run `/reducing-entropy` during planning.

**macOS:** Linux-first, designed cross-platform (D-18); verified in the Phase 7 Mac pass.
</domain>

<decisions>
## Implementation Decisions

> **Scope is pre-locked with the maintainer in ROADMAP.md** (§"Phase 06.2", G-1/G-2a/
> G-2b/cwd-fallback/migration). The decisions below resolve the remaining open HOW
> questions; the locked roadmap scope is the binding contract and is NOT re-litigated.

### Icon as its own attribute (G-1 — revises D-03/D-04)
- **D-01:** **Both a subcommand AND a convenience flag.** Add dedicated
  `wez tab icon <name>` and `wez pane icon <name>` subcommands (mirroring the existing
  `color` / `title` verbs), PLUS a convenience `--icon <name>` flag on the **`title`**
  subcommands only (`wez tab title ... --icon`, `wez pane title ... --icon`). Color
  subcommands do NOT take `--icon`. Register all new surface in `cli/spec.lua` so
  completion + `wez keys` pick it up (6.1 D-16).
- **D-02:** **Icon input accepts a named ICONS key OR any literal emoji/glyph.** The
  curated `title.lua` ICONS map (`node`→💚, `python`→🐍, …) stays the documented
  shortcut; any other input is taken as a literal glyph/text. Keep the map; widen
  acceptance.
- **D-03:** **New carrier `WEZTERM_TAB_ICON`**, emitted via OSC 1337 `SetUserVar` to the
  pane TTY — the same channel as 6.1 D-03. Scene recipes gain an `icon` key at the tab
  level and at `[[pane]]` level (sibling to `color`/`title`).
- **D-04:** **Render = icon left of title** (`💚 api`): `format-tab-title` composes
  `WEZTERM_TAB_ICON` + a single space + `WEZTERM_TAB_TITLE`. Title text stays literal;
  the icon is never folded into the title string.

### Fate of the legacy icon-in-title shortcut (G-1 migration — revises D-04 of 6.1)
- **D-05:** **Removed from steady state.** A title's first word is no longer swapped for a
  glyph — title text is fully literal. Icons come ONLY from the new `icon` attribute.
- **D-06:** **Lightweight CLI parse-and-warn only — nothing more.** When a known
  icon-name is typed as a leading title word, the CLI warns once ("looks like a legacy
  icon-name title — use `wez tab icon` instead") but does NOT swap it. **No `wez doctor`
  gate, no advisory probe, no auto-fix, no persistent migration tracking.** Rationale
  (maintainer, verbatim): *"This is not a massive distributed app, we can remove the
  legacy behavior and forget about someone using legacy config."* A clean reinstall / a
  config edit is an acceptable reset (consistent with 6.1 D-10).

### Tab/pane color split + adopt toggle (G-2a/G-2b — revises D-02)
- **D-07:** **Split carriers.** `wez tab color` writes `WEZTERM_TAB_COLOR` (the tab's own
  stable color); `wez pane color` writes `WEZTERM_PANE_COLOR` (the per-pane accent). They
  no longer share one var — fixing the current clobber where the active pane overwrites an
  explicit tab color.
- **D-08:** **Precedence — explicit tab color ALWAYS wins.** `format-tab-title` resolves:
  (1) the tab's own `WEZTERM_TAB_COLOR` if set; else (2) if `follow_pane_color` is ON, the
  active pane's `WEZTERM_PANE_COLOR`; else (3) neutral (no accent).
- **D-09:** **Opt-in control named `--follow-pane-color`** (CLI flag on `wez tab color`)
  + recipe key **`follow_pane_color`** (tab level), **default OFF**. When ON, a tab with
  no explicit color tracks its active pane's color; when OFF, a colorless tab stays
  neutral. Makes the behavior readable in the TOML/CLI instead of magic.
- **D-10:** **Neutral state = WezTerm's default theme color.** When adopt is OFF and the
  tab has no explicit color, no accent is applied — the tab uses WezTerm's built-in
  active/inactive tab colors. No last-known / sticky color state is tracked.

### `{cwd}`-in-title auto-fallback
- **D-11:** **Fires only when the resolved title is truly empty** (no title set, or set to
  `''` / `reset`). Any explicit non-empty title always wins. Builds on
  `cli/lib/title.lua` `expand_cwd` / `basename`.
- **D-12:** **Applies to both panes AND tabs.** A colorless/labelless pane or tab
  self-labels by its launch-dir basename.
- **D-13:** **With an icon but no title text → icon + cwd basename** (`💚 myrepo`). The
  explicitly-set icon is preserved; the cwd basename fills the empty title slot.

### Claude's Discretion
- The precise shared-module decomposition produced by `/reducing-entropy` (carries 6.1
  D-01) — which helpers land in which `cli/lib/` module under the "one shared path, no
  duplication" invariant.
- Exact warn surface/lifetime/wording for the legacy icon-in-title parse-and-warn (D-06).
- Whether `WEZTERM_PANE_COLOR` is a rename of, or addition alongside, the existing pane
  color var — planner decides under the no-duplication invariant, preserving the 6.1
  two-user-var pane model semantics.
- Exact glyph used for the refreshed seed scenes' `icon` attribute.
</decisions>

- `cli/lib/title.lua` — `ICONS` map, `resolve_title` / `resolve_title_str` (first-word
  glyph swap — **remove the swap from steady state, D-05; widen icon input, D-02**),

- `config/wezterm-setup/format-tab-title.lua` — reads `WEZTERM_TAB_COLOR` /
  `WEZTERM_TAB_TITLE` from the active pane. **Change:** compose `WEZTERM_TAB_ICON` +
  title (D-04); resolve color via the D-08 precedence (tab own > follow-pane >
  neutral); apply the empty-title cwd fallback (D-11/D-13).
- `cli/commands/tab.lua` — color/title read-modify-write. Add `icon` subcommand +
  `--icon` on `title`; emit `WEZTERM_TAB_ICON` (D-03); add `--follow-pane-color`
  flag (D-09); write `WEZTERM_TAB_COLOR` only (D-07).
- `cli/commands/pane.lua` — sibling color/icon/title path. Add `icon` subcommand +
  `--icon` on `title`; write `WEZTERM_PANE_COLOR` for the pane accent (D-07).
- `cli/lib/recipe.lua` + `cli/vendor/tinytoml.lua` — extend schema with `icon` (tab +
  `[[pane]]`) and `follow_pane_color` (tab); map to spec.
- `cli/spec.lua` — register `icon` subcommands, the `--icon` flags, and
  `--follow-pane-color` so completion + `wez keys` pick them up (6.1 D-16).
- `scenes/ai.toml` / `scenes/dev.toml` / `scenes/docker.toml` — refresh seeds to use the
  explicit `icon` attribute (copy-if-absent seeder, 6.1 D-15).

### Established Patterns
- **Pure-core / IO-shell split** — structural template for the shared-path consolidation.
- **Validate-before-emit** — applies to icon + color validation.
- **OSC 1337 `SetUserVar` to the pane TTY** — the locked carrier mechanism (6.1 D-03).
- **Spec-driven completion / `wez keys`** — register all new surface in `cli/spec.lua`.

### Integration Points
- **Icon write:** `wez tab/pane icon` (or `... title --icon`) → OSC `SetUserVar
  WEZTERM_TAB_ICON` to the tab's/pane's TTY.
- **Color write:** `wez tab color` → `WEZTERM_TAB_COLOR`; `wez pane color` →
  `WEZTERM_PANE_COLOR` (split, D-07).
- **Render:** `format-tab-title` composes icon+title (D-04) and resolves color by the
  D-08 precedence; empty title → cwd basename (D-11/D-13).

carrier + render D-03/D-04, cwd-title fallback D-11/D-13) get a manual repro against a
live WezTerm session before integration — per CLAUDE.md "verify before declaring done".

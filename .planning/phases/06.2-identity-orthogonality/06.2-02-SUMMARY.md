# Phase 06.2 Plan 02: Icon CLI surface + color-carrier split Summary

The user-facing half of G-1 (icon as its own attribute) and G-2a/G-2b (tab-vs-pane color
split + explicit follow-pane opt-in) across `wez tab` / `wez pane`, plus the single spec.lua
registration and the only migration surface 6.2 ships (the D-06 legacy-icon parse-and-warn).

## What Was Built

- **Spec registration (Task 1, D-16)** — `cli/spec.lua` registers `tab icon` / `pane icon`
  subcommands (optional positional `value`), `--icon` as an option on the `title` subcommands
  ONLY (not color), `--follow-pane-color` as a flag on `tab color` ONLY, and `icon=` in the
  `--pane` grammar doc string. New `cli/spec_test.lua` (created) asserts each registration via
  argparse `pparse` (protected parse) — including that `--icon` is REJECTED on `color` and
  `--follow-pane-color` is rejected on `pane color`.
- **tab.lua (Task 2)** — re-exports `resolve_icon`; adds `M.run_icon` (emits `WEZTERM_TAB_ICON`);
  `run_color` emits `WEZTERM_TAB_COLOR` and, when `--follow-pane-color` is set, ALSO the locked
  `WEZTERM_TAB_FOLLOW_PANE="1"` (default OFF); `run_title` calls the shared legacy-icon warn and
  supports `--icon` (second independent icon write). Routes `icon` in `M.run`.
- **pane.lua (Task 3)** — `run_color` now writes the SPLIT `WEZTERM_PANE_COLOR` carrier on both
  the normal and reset paths (OSC-11 background unchanged); zero `WEZTERM_TAB_COLOR` references
  remain. Adds `M.run_icon` + `--icon` on title (shared `WEZTERM_TAB_ICON`), and calls the SAME
  shared warn helper with a `wez pane` message variant. Module header updated for the split.
- **Shared legacy-icon warn (D-06)** — `title.warn_legacy_icon_title(text, cmd_prefix, suggest)`
  plus a module-level one-time guard and a `reset_legacy_icon_warn()` test seam live ONCE in
  `cli/lib/title.lua`; both tab and pane reuse it. It warns when a known ICONS-name is the leading
  word of a literal title, never swaps the word, never changes exit status.

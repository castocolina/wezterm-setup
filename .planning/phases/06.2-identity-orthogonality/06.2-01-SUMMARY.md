# Phase 06.2 Plan 01: Pure-core identity helpers Summary

resolve_icon (named-key OR literal-glyph) + the shared empty-title cwd fallback land in
cli/lib/title.lua via RED->GREEN TDD, and the legacy first-word icon swap is removed from
steady state — titles are now fully literal.

## What Was Built

- **`M.resolve_icon(input)` (D-02)** — pure resolver: a known `M.ICONS` name (case-insensitive,
  mirroring the `resolve_title` `:lower()` idiom) maps to its glyph; any other input (literal
  emoji/glyph/text) is returned verbatim; `nil`/`""` -> `""`. No reject — per the threat
  register (T-06.2-01) this module returns a Lua string only and performs no terminal write, so
  OSC/control-byte neutralization stays the emitter's job (`color.build_osc1337` base64).
- **First-word glyph swap removed (D-05)** — `resolve_title` and `resolve_title_str` no longer
  consult `M.ICONS`; words/strings join verbatim (original case preserved). The `reset`/empty
  `-> ""` guards and `expand_cwd` `{cwd}` token handling are kept untouched. The only remaining
  `M.ICONS[...]` lookup in the module is inside `resolve_icon`.
- **`M.fallback_title(title, icon, launch_dir)` (D-11/D-12/D-13)** — pure, reuses `M.basename`:
  a non-empty `title` always wins (D-11); otherwise `basename(launch_dir)` (D-11/D-12); with a
  non-empty `icon` present -> `icon .. " " .. basename` (D-13). This is the SINGLE shared helper
  both the tab-side render (Plan 03) and the pane-side scene loop (Plan 04) will call, so D-12
  ("applies to both panes AND tabs") is one rule, not two divergent copies. Reuses the existing
  `basename` edge contract (`"/" -> "/"`) so odd paths never crash (T-06.2-02).

## Shared Patterns (apply across all relevant files)

### Pattern A — Two-user-var OSC `SetUserVar` emit (THE model the new carriers copy)
**Source:** `cli/lib/color.lua:110-112` (`build_osc1337`) + `cli/commands/pane.lua:96`
```lua
-- color.lua: the ONE builder (base64-encodes the value, neutralizes control bytes)
function M.build_osc1337(varname, value)
  return "\27]1337;SetUserVar=" .. varname .. "=" .. base64_encode(value or "") .. "\7"
end
-- pane.lua run_color: dual-write — OSC 11 background + OSC 1337 user var, one io.write
emit(M.build_osc11(bg_hex) .. M.build_osc1337("WEZTERM_TAB_COLOR", normalized))
```
**Apply to:**
- `WEZTERM_TAB_ICON` (D-03) — `wez tab/pane icon` and `--icon` emit
  `build_osc1337("WEZTERM_TAB_ICON", icon)` exactly like `WEZTERM_TAB_TITLE`
  (`pane.lua:109`).
- `WEZTERM_PANE_COLOR` (D-07) — the per-pane accent carrier. Decision for the
  planner (CONTEXT discretion): rename today's `WEZTERM_TAB_COLOR`-on-pane to
  `WEZTERM_PANE_COLOR`, while `wez tab color` keeps writing `WEZTERM_TAB_COLOR`.
  Both use the identical `build_osc1337` call; only the varname string changes.
- The pane-TARGETED variant (scene loop) uses `build_user_var_octal`
  (`color.lua:119-123`) folded into the self-erasing `printf` line — the SAME
  emitter, octal-rendered. New `WEZTERM_TAB_ICON`/`WEZTERM_PANE_COLOR` escapes go
  into the same `escapes[]` table (`scene.lua:364,371`).

### Pattern B — Validate-before-emit gate
**Source:** `cli/commands/pane.lua:74-78`, `cli/lib/color.lua:62-81`
```lua
local ok, normalized = M.validate_color(args.value)
if not ok then
  io.stderr:write("wez pane color: " .. normalized .. "\n")  -- error string, exit 2
  return 2
end
```
**Apply to:** icon input (D-02 accepts a named ICONS key OR any literal glyph —
so validation is permissive: resolve the name to a glyph, else pass the literal
through; no hard reject). Color split keeps the existing strict
`color.validate_color` gate unchanged.

### Pattern C — Public surface re-exported from the shared lib (D-01, no re-definition)
**Source:** `cli/commands/tab.lua:35-38`, `cli/commands/pane.lua:46-54,103-104`
```lua
local color = require("cli.lib.color")
local title = require("cli.lib.title")
M.validate_color = color.validate_color
M.build_osc1337 = color.build_osc1337
M.ICONS         = title.ICONS          -- pane.lua re-exports the shared map
M.resolve_title = title.resolve_title
```
**Apply to:** any new icon-resolver helper lands in `cli/lib/title.lua` and is
re-exported by BOTH `tab.lua` and `pane.lua`. Do NOT add a local copy.

### Pattern D — Pure-core `*_test.lua` convention (TDD + e2e this phase)
**Source:** `cli/lib/title_test.lua:1-16,59-60` (the canonical shape every test uses)
```lua
local M = require("cli.lib.title")
local pass, fail = 0, 0
local function check(name, cond) ... end
local function eq(name, got, want) check(..., got == want) end
-- ... assertions ...
io.write(string.format("\ntitle_test: %d passed, %d failed\n", pass, fail))
os.exit(fail == 0 and 0 or 1)
```
IO-shell tests stub the seams (`cli/commands/tab_test.lua:56-60`):
```lua
local function with_seams(fn)
  local real_write, real_read, real_iowrite = M.write_tab_title, M.read_current_tab, io.write
  M.write_tab_title = function(str, tab_id) writes[#writes+1] = str; return 0 end
  -- ... capture io.write OSC, run fn, restore ...
end
```
**Apply to:** new icon resolution + cwd-fallback + color-precedence logic gets
pure-core assertions in the matching `*_test.lua`; the carrier-emit and
precedence-render get e2e coverage (live-session repro per CLAUDE.md "verify
before declaring done"). Render-side tests go in
`config/wezterm-setup/format-tab-title_test.lua`.

## Pattern Assignments

### `cli/lib/title.lua` (utility, transform) — icon attribute + cwd fallback core
**Analog:** itself (the 6.1 consolidation).
- **Widen icon input (D-02):** the `M.ICONS` map (`title.lua:11-16`) STAYS as the
  documented shortcut; add a pure `resolve_icon(input)` that returns the glyph for
  a known name (case-insensitive, like `resolve_title:29`) else the literal input
  verbatim. Mirror `resolve_title`/`resolve_title_str`'s `:lower()` lookup idiom.
- **Remove the first-word glyph swap from steady state (D-05):** `resolve_title`
  (`:21-39`) and `resolve_title_str` (`:45-59`) stop swapping `words[1]`/`first`
  for a glyph — title text becomes fully literal. KEEP `reset`/empty → `""` and
  KEEP the `expand_cwd` token handling. Update `title_test.lua:25-41` expectations.
- **cwd-empty fallback (D-11/D-13):** reuse `basename` (`:63-68`) + `expand_cwd`
  (`:76-86`). The fallback rule is "resolved title is empty → `basename(launch_dir)`";
  with an icon present → `icon + " " + basename` (D-13). This is a small pure
  helper here, applied by the render handler and the scene loop.

### `cli/lib/color.lua` (utility, transform) — carrier split
**Analog:** itself. NO new validation logic — the split is purely about which
varname `build_osc1337` is called with. The 10-name palette, alpha handling
(`:62-81`), and builders are reused verbatim.

- **`wez tab color` writes ONLY `WEZTERM_TAB_COLOR` (D-07)** — already true at

### `config/wezterm-setup/format-tab-title.lua` (provider, render) — THE composition + precedence site
**Analog:** itself — the `format-tab-title` handler (`:128-163`).
- **Icon + title composition (D-04):** in the handler, read
  `uv.WEZTERM_TAB_ICON`; compose `icon .. " " .. title` (icon left, single space)
  before `format_label` (`:157`). Title text stays literal.
- **Color precedence (D-08):** replace the single `accent_color` read (`:145`) with
  the 3-step resolution: (1) tab's own `WEZTERM_TAB_COLOR` if set → (2) if
  `follow_pane_color` ON, active pane's `WEZTERM_PANE_COLOR` → (3) neutral
  (`M.DEFAULT_PROFILE`, i.e. WezTerm default — D-10). `resolve_profile` (`:46-61`)

- **cwd fallback (D-11/D-13):** where title resolves empty (`:149-155` fallback

  separate Lua bundle with no CLI `cli/lib` require — the `basename` helper must be
  duplicated here (small, pure) OR the basename is precomputed and shipped as a user
  var. Note the existing lockstep-INVARIANT comment style (`:73-75`) for any logic
  that must mirror the CLI side.
- **Drop legacy `parse_tab_title` from steady state (D-05 echoes 6.1 D-04):** the
  migration-only parser (`:76-89`) was already discardable; with icon-in-title gone

### `cli/spec.lua` (config, CLI tree) — register new surface (D-16)
**Analog:** itself — the `pane`/`tab` registration (`:135-162`).
```lua
-- pane / tab already: command_target -> color/title subcommands. Add a sibling:
local pane_icon = pane:command("icon", "Set or clear this pane's icon")
pane_icon:argument("value", "Icon name (node/python/...) or any literal glyph"):args("?")
pane_title:option("--icon", "Also set the pane icon (name or glyph)")   -- on title only
-- tab mirror: tab:command("icon", ...) + tab_title:option("--icon", ...)

```
Note `--icon` is an `:option` (takes a value, like `--title` at `:160`); `icon` is a
subcommand with one positional (like `color` at `:153`). Register ONLY here — the
command modules implement behavior without re-editing spec (`spec.lua:6-9`).
The `--pane` grammar doc string (`:181-182`) gains `icon=..`.

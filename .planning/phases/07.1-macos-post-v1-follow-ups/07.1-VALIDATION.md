# Phase 07.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Derived from 07.1-RESEARCH.md §Validation Architecture.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Plain `assert()`/`check()`-based Lua test files (no external framework), discovered by `tools/run-tests.sh` |
| **Config file** | none — `tools/run-tests.sh` discovers `*_test.lua` under `cli/` and `tests/` |
| **Quick run command** | `lua5.4 tests/cli/<touched>_test.lua` (keg `lua@5.4`) |
| **Full suite command** | `bash tools/run-tests.sh` + `bash tools/verify-macos.sh` |
| **Estimated runtime** | suite ~a few seconds; single file sub-second |

> **Harness caveat:** `lua5.4` is keg-only on this Mac — `export PATH="$(brew --prefix lua@5.4)/bin:$HOME/.luarocks/bin:$PATH"` (the form proven green in 07-05) before running, or use `LUA_BIN=lua`. The 8 unrelated Lua-5.5 `<const>` failures are a SEPARATE deferred follow-up, not 07.1's concern.

---

## Sampling Rate

- **After every task commit:** Run the touched test file (`lua5.4 tests/cli/<file>_test.lua`) — sub-second.
- **After every plan wave:** Run `bash tools/run-tests.sh` (full Lua suite) + `bash tools/verify-macos.sh`.
- **Before `/gsd-verify-work`:** Full suite green AND `verify-macos.sh` FAIL=0.
- **Max feedback latency:** < 10 seconds (quick), < 60s (full).

# Phase 07.1 Plan 02: wez keys --json dkjson Bundle-Require Fix Summary

Fixed the cross-platform `wez keys --json` bug (macOS deviation #5): the `--json`
branch did a bare `require("dkjson")` that fails `module 'dkjson' not found` in the
shipped luastatic binary; replaced it with the project's proven dual-resolve idiom
(`cli.vendor.dkjson` first, bare fallback, unavailable-encoder guard) and pinned it
with a RED-first bundle-path regression.

## What Was Built

- **Task 1 (RED, `4d2a1db`):** Extended `tests/cli/keys_test.lua` with a new block:
  (1) a positive round-trip via `require("cli.vendor.dkjson")` (the BUNDLE module name)
  that encodes→decodes `keys.build_json(classified, conflicts)` and asserts `.bindings`/
  `.conflicts` survive; (2) a source-text guard that reads `cli/commands/keys.lua` and
  asserts it contains `cli.vendor.dkjson` and lacks a bare `require("dkjson")`. The guard
  failed as expected (RED): `has_bundle=false has_bare=true`, exit 1, all other checks green.
- **Task 2 (GREEN, `0b15a9a`):** Replaced the `--json` branch body in `cli/commands/keys.lua`
  with `local ok, json = pcall(require, "cli.vendor.dkjson")` then a bare-name fallback and a
  guard (`if not ok or type(json) ~= "table" then io.stderr:write(...); return 1 end`) before
  encoding. Emit path (`json.encode(M.build_json(entries, conflicts), { indent = true })`)
  unchanged. Mirrors `cli/lib/shell.lua:32-33` exactly. `tools/build.sh` untouched.

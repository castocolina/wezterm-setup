<decisions>
## Implementation Decisions

### Scene PATH fix (deviation #6 / follow-up A-4)
- **D-01:** `tools/bootstrap-wezterm.sh` `install_macos()` MUST symlink the bundled WezTerm CLI onto the user PATH — `ln -sfn "${HOME}/Applications/WezTerm.app/Contents/MacOS/wezterm" "${BIN_DIR}/wezterm"` — exactly mirroring `install_linux()` (`bootstrap-wezterm.sh:450`). Sudo-free, user-path only (`BIN_DIR` = `~/.local/bin`), no shell-rc edits, no broad PATH manipulation. This is the smallest correct change and restores Linux↔macOS symmetry so `wez scene new`/`wez scene launch` resolve `wezterm` out of the box.
- **D-02:** Add/extend a test proving the symlink is created + resolvable on macOS (mirror the Linux symlink assertion), and ideally a regression that `wez scene` no longer errors `mux returned a non-numeric pane id` once the symlink exists. Verify live (real install → `wez scene launch docker` succeeds).
- **D-03:** Update the runbook deviation #6 / A-4 + REQUIREMENTS/ROADMAP SCEN footers from "follow-up / not yet shipped" to "fixed in 07.1" once the symlink ships.

### `wez keys --json` bug (deviation #5) — FOLDED INTO 07.1
- **D-04:** Fix `cli/commands/keys.lua:262` — it does `require("dkjson")` but the vendored module lives at `cli/vendor/dkjson.lua`. Change to the correct require path (`require("cli.vendor.dkjson")` or the project's established vendor-require convention) AND ensure the module is included in the luastatic bundle (so the shipped binary resolves it, not just the dev launcher).
- **D-05:** Add a `wez keys --json` parse regression test (output is jq/`json.tool`-valid, exit 0) so it can't silently regress. This is cross-platform — verify on this Mac; the fix benefits Linux equally.

### Apple-Silicon end-user first-launch check (INST-08)
- **D-06:** Deliver a **documented, self-run checklist + script** an end-user executes on real Apple Silicon hardware (no agent/CI hardware required, non-gating). Steps: download the published `v1.0.0` `wez-macos-aarch64` asset (+ verify `.sha256`), exercise Gatekeeper first-launch on the ad-hoc-codesigned binary, run `wez doctor` (expect exit 0), confirm version, and report the outcome. Record where the result lands (e.g., a runbook section / INST-08 status note) when someone runs it.
- **D-07:** This stays NON-gating (D-01b). INST-08's macOS status flips only when a real Silicon run is reported; until then it remains the single open macOS item, explicitly tracked, not blocking.

### Keybindings documentation (keep-both locked)
- **D-08:** No keybinding *behavior* change. `SUPER` already maps to Cmd on macOS (Cmd+T/W/K/+/− work); the `Ctrl+Shift` chords are intentional cross-platform fallbacks and stay on macOS. Record this rationale durably as a short note in `docs/` and/or the macOS runbook (`docs/macos-verification.md`) so it survives sessions and is discoverable as a decision — the rationale currently lives only in chat/handoff.

### Claude's Discretion
- Exact test file placement/names and the precise vendor-require idiom (match existing `cli/vendor/` conventions).
- Whether the Silicon self-check ships as a standalone script, a runbook section, or both — planner/researcher to choose the lowest-friction form.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `install_linux()` symlink logic (`bootstrap-wezterm.sh:450`, `ln -sfn ... "${BIN_DIR}/wezterm"`) — the exact precedent the macOS symlink should mirror; `BIN_DIR` already resolves to `~/.local/bin` in this file.
- `cli/vendor/dkjson.lua` already vendored — the `keys --json` fix is a require-path correction + bundle inclusion, not a new dependency.
- The Phase 7 macOS verification harness (`tools/verify-macos.sh`, `docs/macos-verification.md`) — the place to record the Silicon self-check and the keybindings note.

### Established Patterns
- Sudo-free, user-path-only installs (`~/.local/bin`, `~/Applications`) — the PATH fix MUST stay within this.
- luastatic bundling — any `require` in a CLI command must resolve inside the static binary (the `keys --json` bug is precisely a bundle/require mismatch).
- TDD (`workflow.tdd_mode = true`) — RED test first for the symlink + the `keys --json` parse.

### Integration Points
- `install_macos()` is invoked by the installer flow (`tools/install.sh` → setup → bootstrap); the symlink lands during a normal install/update, so the E2E install test path covers it.

</code_context>

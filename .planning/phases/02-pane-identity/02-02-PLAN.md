<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pane user_vars -> format-tab-title handler | Values in `tab.active_pane.user_vars` (set by any process in the pane via OSC 1337) cross into tab-bar render logic |
| handler -> tab-bar render | Returned format-runs (Text + Color) are rendered by WezTerm's tab bar |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Tampering | M.resolve_profile | mitigate | `WEZTERM_TAB_COLOR` is looked up against the closed `color_profiles` table (or treated as a hex bg); any unrecognized/garbage value falls back to `DEFAULT_PROFILE` — a crafted color name cannot inject arbitrary render state, only select an existing profile or the default |
| T-02-02-02 | Tampering | format-tab-title Text run | accept | `WEZTERM_TAB_TITLE` is rendered as a `{Text=...}` run; WezTerm treats format-run Text as display text (not an escape stream), so embedded control bytes are not re-interpreted as terminal escapes at the tab-bar layer; title length is bounded by `max_width` truncation (DoS bound) |
| T-02-02-03 | Denial of Service | format-tab-title handler | mitigate | the handler is pure table lookups + a bounded truncation per render; no loops over untrusted-length input beyond the truncated label, so a very long title cannot stall rendering |
</threat_model>

<objective>
Resolve the one unproven mechanism in Phase 2 BEFORE any CLI wiring depends on it: can a single WezTerm pane be made translucent without affecting its siblings? Per the project's hypothesis-first rule (CLAUDE.md, docs/agent-iteration.md), this is an experiment in `.tmp/h04-perpane-opacity/` (gitignored) with a recorded manual repro against a real running WezTerm, producing a durable YES/NO verdict in `02-01-SUMMARY.md`.

Purpose: 02-03 (`wez pane color`) and 02-04 accept opacity input (alpha-in-rgba and a `--opacity` flag) but their rendering behavior is GATED on this verdict (D-03/D-06). Without the spike, 02-03 would have to assume opacity works or not — guessing. This plan de-risks that decision with evidence.

Output: `.tmp/h04-perpane-opacity/` experiment scripts + `FINDINGS.md`, and the committed `02-01-SUMMARY.md` carrying the verdict + locked downstream decision. NO shipped source code changes in this plan.
</objective>

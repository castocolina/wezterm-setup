<objective>
Implement `wez pane color <name|hex|rgba>` and `wez pane color reset` in a new `cli/commands/pane.lua` module, registered as the `pane` subcommand in `cli/spec.lua`. The command validates the input against a curated 10-name color list or a hex/#rgb/#rrggbb/#rrggbbaa pattern BEFORE emitting any escape sequence (D-01), then dual-writes an OSC 11 (muted per-pane background) and an OSC 1337 SetUserVar `WEZTERM_TAB_COLOR` (D-02), wired to the color-profile table established in 02-02 so the tab-bar accent and pane background stay visually consistent.

Purpose: This is the user-facing entry point for Phase 2's pane-identity feature — the first command a user runs to color-code a pane, and the producer of the `WEZTERM_TAB_COLOR` user var that 02-02's `format-tab-title` event handler consumes to render the tab-bar accent.

Output: `cli/commands/pane.lua` (new module: pure color-model/validation/OSC-builder functions + `run()` live wiring), `cli/spec.lua` updated to register `pane`/`color` in the command tree and allow-list. Verified live: color persists across focus switches, reset restores defaults, invalid input is rejected with no side effects.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03-01 | Tampering | `cli/commands/pane.lua` M.run | mitigate | validate-before-emit (D-01): `M.validate_color` rejects any input not matching the 10-name allow-list or the `^#%x+$` hex pattern (3/4/6/8 digits) BEFORE any `io.write` call — a crafted string containing raw `\27` (ESC), BEL, or ST cannot reach `build_osc11`/`build_osc1337` because it fails the regex match and `M.run` returns exit 2 with zero stdout bytes written |
| T-02-03-02 | Tampering | `cli/commands/pane.lua` M.build_osc1337 | mitigate | the `WEZTERM_TAB_COLOR` payload is always the *normalized* color name or hex string (already validated against the closed pattern), then base64-encoded before insertion into the OSC 1337 sequence — base64 output is restricted to `[A-Za-z0-9+/=]`, which cannot contain ESC/BEL/ST regardless of input, providing defense-in-depth even if validation were bypassed |
| T-02-03-03 | Elevation of Privilege | `cli/spec.lua` SUBCOMMANDS allow-list | mitigate | `"pane"` is added to the closed `SUBCOMMANDS` array consumed by `cli/wez.lua`'s dispatcher (T-01-02 allow-list pattern); module resolution via `name:gsub("%-","_")` maps `"pane"` -> `cli.commands.pane` with no new alias entry, preserving the existing closed-set guarantee |
| T-02-03-04 | Information Disclosure | stderr error messages | accept | `validate_color` echoes the raw user-supplied string back in the "unknown color" error message; this is local-CLI stderr (not a network response), no sensitive data is reflected, and it is necessary for usability |
| T-02-03-05 | Denial of Service | `M.run` reset path | accept | reset emits a fixed, hardcoded OSC 111 + empty-payload OSC 1337 sequence with no user input involved — no injection surface |

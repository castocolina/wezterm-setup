## Rolling release shape — release identity

| Option | Description | Selected |
|--------|-------------|----------|
| Fixed `nightly` tag, prerelease | Single release force-repointed each run via `--clobber`; stable URL; mirrors upstream wezterm | |
| Datestamped prereleases | Each nightly tagged `nightly-YYYYMMDD`; `nightly` resolved by querying newest via API | ✓ |

**User's choice:** Datestamped prereleases
**Notes:** Prompted a clarification on GitHub retention — release assets are permanent (not the
90-day Actions-artifact store), so datestamped releases accumulate and require pruning (see cadence).

## Rolling release shape — cadence + retention

| Option | Description | Selected |
|--------|-------------|----------|

| Weekly, keep last 5, skip if unchanged | Weekly cron, no-op if main unchanged, prune to newest 5 | ✓ |
| Daily, keep all | Daily cron, skip-if-unchanged, never prune (unbounded history) | |

**User's choice:** Weekly, keep last 5, skip if unchanged
**Notes:** Channel keyword stays `nightly` despite weekly cadence (flagged for possible later rename to `rolling`).

## CI routing — workflow wiring

| Option | Description | Selected |

## What was built

- **Task 1 — trigger + routing.** Added `schedule: - cron: "17 6 * * 1"` (weekly,
  Mon 06:17 UTC) alongside the unchanged `push: tags: ["v*"]` and `workflow_dispatch`.
  Added a `Resolve channel (D-07)` step (right after Checkout) that branches on
  `$GITHUB_REF`: a `refs/tags/*` ref writes `CHANNEL=stable` + `TAG=$GITHUB_REF_NAME`;
  any other ref writes `CHANNEL=nightly` + `TAG=nightly-$(date -u +%Y%m%d)` to
  `$GITHUB_ENV`. No manual channel input (T-06.3-02-03). `permissions: contents: write`
  unchanged (least privilege).
- **Task 2 — nightly publish + skip guard.** Added `Skip if unchanged (nightly only)`
  step (`id: nightly_guard`, `if: env.CHANNEL == 'nightly'`): reads the newest
  `nightly-*` release's `built-from: <sha>` marker from its notes body (`gh release
  view --json body`), compares to `git rev-parse HEAD`, and emits `unchanged=true|false`
  as a step output — it does NOT `exit 0` the whole job (the stable path must still run).
  Repointed `Ensure release exists` + `Upload release asset` to be channel-aware: both
  use the resolved `$TAG` (serves `nightly-YYYYMMDD`), both skip on a nightly unchanged
  no-op via `if: ${{ !(env.CHANNEL == 'nightly' && steps.nightly_guard.outputs.unchanged == 'true') }}`.
  Nightly create passes `--prerelease` and embeds `built-from: <sha>` in the notes
  (with same-UTC-date in-place `gh release edit` refresh when the dated release already
  exists). Stable keeps the existing non-prerelease `--generate-notes` shape. The
  asset-name + per-asset `.sha256` block and the `--clobber` upload are byte-identical
  (P6-D08).
- **Task 3 — prune.** Added `Prune old nightly releases (D-06)` after the upload,
  guarded `if: ${{ env.CHANNEL == 'nightly' && steps.nightly_guard.outputs.unchanged != 'true' }}`.
  Lists `nightly-*` tags only (`gh release list --json tagName --jq` select on the
  `nightly-` prefix), sorts desc, slices off the newest 5 (`"${nightly_tags[@]:5}"`),
  and deletes the remainder — each `gh release delete` is fenced behind a
  `case "$tag" in nightly-*)` re-assertion so a `v*` stable release can never be reached
  (T-06.3-02-02).

## Deviations from plan

- **[Rule 1 — Bug] `built-from` marker indentation.** A first attempt embedded the
  notes via a YAML-indented multi-line shell string, which would have prepended literal
  leading whitespace to the `built-from:` line and broken the guard's `^built-from:`
  anchored read-back. Fixed by building the notes with `printf 'Automated nightly
  build.\n\nbuilt-from: %s\n'` so the marker is column-0. (Folded into commit `4aef3d0`.)
- **[Rule 2 — Missing critical functionality] Same-UTC-date re-run notes refresh.** On a
  same-day re-run with a NEW commit, the dated `nightly-YYYYMMDD` release already exists,
  so a plain `view-or-create` would skip `create` and leave a STALE `built-from` SHA in
  the notes, defeating the next run's skip guard. Added a `gh release edit "$TAG"
  --prerelease --notes "$notes"` branch on the already-exists path to refresh the marker
  in place. (Folded into commit `4aef3d0`.)

No architectural (Rule 4) changes. No package installs.

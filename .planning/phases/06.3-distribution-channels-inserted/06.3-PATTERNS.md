## Pattern Assignments

### `.github/workflows/release.yml` (config, event-driven + batch)

**Analog:** its own existing tag-triggered `build` job.

**Trigger block to extend** (lines 24-31) — add `schedule:` alongside the existing
`push.tags` + `workflow_dispatch`:
```yaml
on:
  push:
    tags:
      - "v*"
  workflow_dispatch:
  # ADD (D-07): schedule trigger -> nightly publish + prune
  # schedule:
  #   - cron: "<Claude's discretion: weekly, e.g. Monday UTC>"
```

**Channel-routing pattern (D-07).** The existing `if:` guards already branch
publish behavior on the ref — extend the SAME mechanism. A tag ref = stable; any
other (schedule/dispatch) = nightly. Existing guard at line 92 / 104:
```yaml
- name: Ensure release exists
  if: startsWith(github.ref, 'refs/tags/')
```
New nightly steps invert this guard (`if: !startsWith(github.ref, 'refs/tags/')`)
or use an explicit channel-resolution step writing `CHANNEL` to `$GITHUB_ENV`.

**Idempotent release-create + upload pattern to REUSE verbatim** (lines 91-109) —
the nightly publish uses the SAME `view-or-create-or-view` + `--clobber` shape,
only the tag changes from `$GITHUB_REF_NAME` to a computed `nightly-YYYYMMDD`:
```yaml
- name: Ensure release exists
  env: { GH_TOKEN: ${{ github.token }} }
  run: |
    gh release view "$TAG" >/dev/null 2>&1 \
      || gh release create "$TAG" --title "$TAG" --generate-notes --prerelease \
      || gh release view "$TAG" >/dev/null 2>&1
- name: Upload release asset
  env: { GH_TOKEN: ${{ github.token }} }
  run: gh release upload "$TAG" "$WEZ_ASSET" "$WEZ_ASSET.sha256" --clobber
```
Nightly adds `--prerelease` (D-03/D-04: so `/releases/latest` excludes it).

**Asset naming + checksum block to reuse unchanged** (lines 70-81) — sources
`tools/lib/platform.sh`, `wez-$(platform_os)-$(platform_arch)`, portable
`sha256sum || shasum -a 256`. Carries over byte-identically to nightly.

**Skip-if-unchanged guard (D-05)** — new step: compare `git rev-parse HEAD` to the
SHA recorded on the last `nightly-*` release; no-op if equal. New logic, but keep it
in YAML as trigger-plumbing (the D-01 CI exception, see Shared Patterns).

**Prune (D-06)** — new step after publish: `gh release list`, filter `nightly-*`,
sort desc, slice off the newest 5, `gh release delete` the rest. New logic.

**D-12 matrix-friendly constraint:** factor build/checksum/publish/prune as
per-target steps so Phase 7 can wrap them in `strategy.matrix` without rewriting
nightly logic. Do NOT add macOS legs here.

### `tools/build.sh` `download_release()` (utility, file-I/O + transform)

**Analog:** `tools/bootstrap-wezterm.sh` channel machinery (the WezTerm-*app*
selector — D-08 says mirror its SHAPE, not its target).

**The pin to replace** (build.sh lines 49-51):
```bash
WEZ_RELEASE_TAG="${WEZ_RELEASE_TAG:-v0.1.0}"
WEZ_RELEASE_BASE="${WEZ_RELEASE_BASE:-https://github.com/castocolina/wezterm-setup/releases/download}"
```
Introduce `WEZ_CHANNEL="${WEZ_CHANNEL:-nightly}"` (D-02/D-08). `WEZ_RELEASE_TAG`
stays as the explicit-pin escape hatch (the third addressable option, D-01).

**Channel-resolution pattern to MIRROR** — `bootstrap-wezterm.sh`
`resolve_want_datestamp()` (lines 139-147) + `latest_nightly_datestamp()`
(lines 96-132). For `wez`-binary resolution (D-03):
- `stable` → GitHub `/releases/latest` (excludes prereleases → nightlies filtered out).
- `nightly` → newest `nightly-*` prerelease (mirror `latest_nightly_datestamp` shape).
- `<vX.Y.Z>` → use literally.

**No-TTY abort + TTY picker pattern to MIRROR** — `bootstrap-wezterm.sh`
`select_release()` (lines 250-297): no-TTY (`[ ! -t 0 ]`) branch resolves
deterministically from the env var; TTY branch prints a numbered picker and reads a
pick. The `wez`-binary picker offers nightly / newest stable / recent tags.

**Fetch + checksum-verify-before-chmod pattern to REUSE verbatim** (build.sh
download_release lines 130-190): curl-or-wget `fetch()`, `mktemp`, RETURN trap,
download asset + `.sha256`, portable digest compare BEFORE `chmod +x`, abort
non-zero on mismatch. Only the URL's tag segment becomes channel-resolved.

**D-01 boundary note:** build.sh comment block (lines 1-36) documents "bootstrap
GLUE only — the only decision is which build PATH." Keep channel resolution as the
minimal trigger-plumbing exception; do not grow install/version policy in bash.

### `cli/spec.lua` (config, registry)

**Analog:** the existing `update` and `uninstall-state` registrations (same file).

Three coordinated edits (the "3-place registration" the tests assert, see
update_test.lua lines 8/45). Add `uninstall` to:

1. `CATEGORIES` table (lines 39-52) — `["uninstall"] = "install",`
2. `SUBCOMMANDS` list (lines 55-68) — add `"uninstall",`
3. `build_parser()` command + flags (mirror `uninstall-state` at lines 114-118):
```lua
local uninstall = parser:command("uninstall", "Remove wezterm-setup (block, config, wez binary, backups)")
uninstall:flag("--yes", "Skip the confirmation prompt (required on a non-TTY pipe)")
uninstall:flag("--keep-config", "Preserve ~/.config/wezterm/wezterm-setup/")
```

### `cli/commands/uninstall.lua` (NEW — command, front door → delegate)

**Analog:** `cli/commands/update.lua` — the canonical "thin Lua front door that
decides, then delegates to the engine/launcher" pattern (D-09).

**Module shape to mirror** (update.lua lines 45-48, 247-305):
```lua
local install_state = require("cli.commands.install_state")  -- for shquote
local uninstall_state = require("cli.commands.uninstall_state")  -- the engine (D-09)
local M = {}
function M.run(args) ... end
return M
```

**Delegation-to-engine pattern (D-09):** `wez uninstall` is a front door over
`uninstall_state.run()` — do NOT re-implement removal. Map the surfaced flags
straight through:
```lua
local engine_args = {
  keep_config = args.keep_config,
  keep_cli    = args.keep_cli,
  keep_backup = args.keep_backup,
}
```
Then call `uninstall_state.M.run(engine_args, seams)` (uninstall_state.lua line 164).

**Confirm-then-remove + no-TTY abort pattern (D-11)** — mirror the no-TTY
determinism rule from bootstrap-wezterm.sh `select_release()` (lines 251-266) and
update.lua's clean-exit messaging: on a TTY with no `--yes`, prompt for
confirmation via `io.read`; on a non-TTY (`io.stdin` not a tty) WITHOUT `--yes`,
abort with a clear message and non-zero (mirrors the D-03 no-TTY abort). `--yes`
skips the prompt.

**Binary self-deletion LAST (D-10).** The engine already removes the cli binary via
`remove_cli` (uninstall_state.lua lines 135-138, plain `os.remove`). The front door
must ORDER removal so the running `wez` binary is unlinked as the FINAL step
(safe on Linux/macOS: inode persists until process exit). Either reorder within the
engine call or have the front door perform the binary unlink itself after the engine
returns for the non-keep-cli case. This is the one piece of NEW ordering logic.

**shquote for any shelled path (CR-02):** `install_state.shquote(...)` — see
update.lua lines 197-199, uninstall_state.lua line 130.

### `tools/uninstall.sh` + `Makefile` (utility/config, glue)

**Analog:** the existing `uninstall` target + `tools/uninstall.sh` (self).

`tools/uninstall.sh` (lines 49-56) already translates `KEEP_*` env → flags and
delegates to `wez uninstall-state`. Repoint the delegation to the new front door
(`"${WEZ}" uninstall` instead of `uninstall-state`) so the documented user command
and the Makefile path stay consistent (D-09). Add `--yes` to the FLAGS array since a
`make uninstall` invocation is non-interactive (the front door requires `--yes` on
non-TTY per D-11):
```bash
FLAGS=(--yes)            # non-interactive make path needs --yes (D-11)
keep_flag "${KEEP_CONFIG:-}" && FLAGS+=(--keep-config)
keep_flag "${KEEP_CLI:-}"    && FLAGS+=(--keep-cli)
keep_flag "${KEEP_BACKUP:-}" && FLAGS+=(--keep-backup)
"${WEZ}" uninstall "${FLAGS[@]}"
```
`Makefile` `uninstall` target (line 39-40) needs no change (it already passes
`KEEP_*` env through to `tools/uninstall.sh`).

## Shared Patterns

### D-01 glue boundary (applies to ALL files this phase touches)
**Source:** stated in every script header — build.sh lines 1-36, uninstall.sh
lines 1-22, platform.sh lines 7-16, release.yml lines 9-12.
**Rule:** scripts/YAML make NO version/channel/removal DECISIONS; logic lives near
the Lua binary. CI routing (D-07: a `github.ref` branch) and channel selection in
build.sh are the ALLOWED trigger-plumbing exceptions — keep them minimal.

### No-TTY deterministic abort
**Source:** `tools/bootstrap-wezterm.sh` `select_release()` lines 251-266.
**Apply to:** `build.sh` `WEZ_CHANNEL` resolution (default nightly on pipe) and
`cli/commands/uninstall.lua` (`--yes` required on non-TTY, else abort).
A non-interactive path resolves deterministically rather than hanging on a prompt.

### gh release idempotent create + `--clobber` upload
**Source:** `release.yml` lines 91-109 (also `tools/publish.sh` runs the identical
upload). **Apply to:** the new nightly publish steps in release.yml — same shape,
only the tag and `--prerelease` flag differ.

### Per-asset `.sha256` contract (P6-D08)
**Source:** release.yml lines 70-81 (produce) + build.sh lines 165-183 (verify).
**Apply to:** nightly assets (produced identically) and `WEZ_CHANNEL` downloads
(verified identically — verify BEFORE chmod, abort on mismatch).

### Thin-front-door-over-engine (delegate, don't re-implement)
**Source:** `cli/commands/update.lua` (fronts the shared launcher) — module loads
the engine, decides, delegates, surfaces the exit code. **Apply to:**
`cli/commands/uninstall.lua` fronting `uninstall_state` (D-09).

### shquote every shelled path (CR-02)
**Source:** `cli/commands/install_state.shquote` (used in update.lua 197-199,
uninstall_state.lua 130). **Apply to:** any path/arg `uninstall.lua` passes to a shell.

### Lua test harness + auto-discovery
**Source:** `tests/cli/*_test.lua` header (lines 17-36) + `tools/run-tests.sh`
(globs `tests/**/*_test.lua`, runs each under lua5.4). **Apply to:** the new
`tests/cli/uninstall_test.lua` — co-locate, copy the header, no runner edit needed.

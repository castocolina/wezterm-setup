## What shipped

A rolling nightly channel was added to the existing tag-triggered `release.yml` as ONE
workflow with two triggers, branching on `github.ref` (D-07):

- **Trigger + routing (D-07)** — `schedule: cron "17 6 * * 1"` (weekly, Mon 06:17 UTC) +
  `workflow_dispatch`, alongside the unchanged `push: tags: ["v*"]`. A `Resolve channel`
  step writes `CHANNEL=stable` + `TAG=$GITHUB_REF_NAME` for a tag ref, else
  `CHANNEL=nightly` + `TAG=nightly-$(date -u +%Y%m%d)`. No manual channel input.
  `permissions: contents: write` unchanged (least privilege).
- **Nightly publish + skip-if-unchanged (D-04/D-05)** — nightly publishes a datestamped
  `nightly-YYYYMMDD` `--prerelease`, embedding a column-0 `built-from: <sha>` marker in the
  notes; reuses the idempotent-create + `--clobber` upload + per-asset `.sha256` contract
  (P6-D08) byte-identically. A `Skip if unchanged` step compares HEAD to the last nightly's
  `built-from` SHA and emits `unchanged=true|false` (step output, NOT a job-wide `exit 0`, so
  the stable path is unaffected); same-UTC-date re-runs refresh the marker via `gh release edit`.
- **Prune (D-06)** — keeps the newest 5 `nightly-*` releases, each `gh release delete` fenced
  behind a `case "$tag" in nightly-*)` re-assertion so a `v*` stable release can never be deleted.
- **Matrix-friendly (D-12)** — single `ubuntu-latest` job, steps factored so Phase 7 can add
  the two macOS legs without rewriting nightly/publish/prune logic. NO macOS work here.

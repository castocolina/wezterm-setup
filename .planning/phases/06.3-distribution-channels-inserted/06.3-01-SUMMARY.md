# Phase 06.3 Plan 01: `wez uninstall` Front Door Summary

**A first-class `wez uninstall` command — a thin Lua front door over the audited `uninstall_state` engine that confirms-then-removes everything on a TTY, requires `--yes` on a non-TTY pipe (D-11), surfaces the `--keep-*` flags, and self-deletes the running wez binary LAST (D-10); `tools/uninstall.sh`/`make uninstall` repointed to it.**

## Accomplishments
- New `cli/commands/uninstall.lua`: thin front door over `uninstall_state` (D-09) — no duplicated removal logic.
- D-11 no-TTY gate: a non-interactive pipe without `--yes` aborts non-zero and removes NOTHING (engine never reached); `--yes` proceeds.
- D-10 binary-self-delete-LAST: engine called with `keep_cli=true`, then the running `wez` binary is `os.remove`d as the final step.

## Decisions Made
- Front door forces `keep_cli=true` on the engine then unlinks the binary itself LAST (D-10 ordering belongs to the front door).
- Non-TTY-without-`--yes` aborts before the engine is ever called (D-11/D-03) — zero accidental removal via a stray pipe.
- tty probe uses `ok == true or ok == 0` (the codebase's own `run_status` idiom) to dodge the Lua 5.4 standalone `== 0` always-false bug.
- `tools/uninstall.sh` left as decision-free glue; Makefile unchanged (already threads KEEP_* env).

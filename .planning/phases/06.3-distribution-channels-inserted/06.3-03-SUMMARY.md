# Phase 06.3 Plan 03: Bootstrapper WEZ_CHANNEL Selector Summary

Replaced the hardcoded `WEZ_RELEASE_TAG=v0.1.0` channel pin in `tools/build.sh`
`download_release()` with a `WEZ_CHANNEL=nightly|stable|<vX.Y.Z>` selector
(default `nightly`, D-02/D-08): a no-TTY `curl|bash` pipe resolves deterministically
and never hangs; a TTY shows a numbered picker; `stable`→`/releases/latest`,
`nightly`→newest `nightly-*` prerelease, `<vX.Y.Z>`→literal — all while keeping the
verify-SHA-256-before-chmod checksum gate (P6-D08) byte-identical and failing loud
on a degraded resolution.

## What Was Built

- **`tools/build.sh` — `WEZ_CHANNEL` selector + `resolve_channel_tag()`**
  - `WEZ_CHANNEL="${WEZ_CHANNEL:-nightly}"` near the existing pins; the hardcoded
    `WEZ_RELEASE_TAG:-v0.1.0` default is **gone**. `WEZ_RELEASE_TAG`, when set,
    now forces `WEZ_CHANNEL` to that literal tag (the explicit-pin escape hatch,
    D-01) so a legacy `WEZ_RELEASE_TAG=v0.1.0` caller keeps working.
  - `WEZ_RELEASE_REPO` (`castocolina/wezterm-setup`) + `WEZ_RELEASE_API`
    (`https://api.github.com`) added for the channel API queries; both
    override-friendly.
  - `_api_fetch()` — a curl-or-wget fetch-to-stdout helper for the API queries
    (no third fetcher added; mirrors the existing curl/wget shape).
  - `resolve_stable_tag()` → `GET /repos/<repo>/releases/latest` `.tag_name`
    (prereleases excluded, so the Plan 02 nightlies auto-filter out, D-03).
  - `list_nightly_tags()` / `resolve_nightly_tag()` → the newest `nightly-*`
    prerelease tag, via `tr ',' '\n'` + `grep -oE` field extraction (NO jq —
    mirrors `latest_nightly_datestamp` shape).
  - `resolve_channel_tag()` — no-TTY (`[ ! -t 0 ]`) resolves deterministically
    from `WEZ_CHANNEL` (default nightly), logging the choice to stderr (stdout
    stays the tag); an explicit literal tag short-circuits; an interactive TTY
    with the symbolic default presents a numbered picker (1=nightly /
    2=newest stable / 3+=recent tags) mirroring `select_release()`.
  - **Fail-loud:** a failed/empty resolution `return 1`s and `download_release()`
    aborts BEFORE constructing any URL — never falling through to an empty/`latest`
    segment that would fetch an unverified asset (T-06.3-03-03).
  - The resolved tag is wired into `url`/`sums_url`; the verify-SHA-256-before-chmod
    block, the per-asset `.sha256` fetch, the mismatch abort, and the
    `chmod +x`-only-after-verify ordering are **byte-identical** (P6-D08).
  - Added a `BASH_SOURCE/$0` sourcing guard around `main "$@"` so the unit test can
    source the script and exercise the resolver without running a build.
- **`tests/cli/build_channel_test.lua`** — regression-guard (auto-discovered by
  `tools/run-tests.sh`): default-nightly, the 3 resolution arms, no-TTY
  determinism, checksum-gate-survives-unbypassed (incl. verify-before-chmod
  ordering at the text level), fail-loud on empty resolution, plus sourced
  behavior asserts (literal arm verbatim, escape hatch, unreachable-API fail-loud).

### Recorded Manual Repro (CLAUDE.md "verify before declaring done")

No live release download triggered — resolution-only (the asset fetch stays gated
behind `WEZ_REMOTE_BOOTSTRAP=1` + a published asset).

**(a) Literal arm — `WEZ_CHANNEL=v9.9.9` echoes verbatim:**
```
$ WEZ_CHANNEL=v9.9.9 bash -c '. tools/build.sh >/dev/null 2>&1; resolve_channel_tag' </dev/null
[build] no TTY on stdin -> WEZ_CHANNEL is an explicit tag: v9.9.9   # (stderr)
v9.9.9                                                              # (stdout)
exit=0
```

**(a2) Explicit-pin escape hatch — `WEZ_RELEASE_TAG=v0.1.0` → `v0.1.0`:**
```
$ WEZ_RELEASE_TAG=v0.1.0 bash -c '. tools/build.sh >/dev/null 2>&1; resolve_channel_tag' </dev/null
[build] no TTY on stdin -> WEZ_CHANNEL is an explicit tag: v0.1.0   # (stderr)
v0.1.0                                                              # (stdout)
exit=0
```

**(b) No-TTY + no channel → deterministically nightly, logs to stderr, never hangs**
(unreachable API forces the nightly fetch to fail fast; resolved under a 10s
`timeout`, so the path is provably non-blocking):
```
$ timeout 10 bash -c 'WEZ_RELEASE_API=http://127.0.0.1:0 ; . tools/build.sh >/dev/null 2>&1; resolve_channel_tag' </dev/null
[build] no TTY on stdin -> resolving the rolling 'nightly' channel (D-02 default)            # (stderr)
[build] ERROR: could not resolve a nightly release tag — refusing to install an unverified asset  # (stderr)
# stdout: (empty — no tag emitted on a failed nightly resolution)
```

**(c) Fail-loud — degraded/empty resolution returns non-zero AND aborts before `chmod +x`:**
```
$ timeout 10 bash -c 'WEZ_RELEASE_API=http://127.0.0.1:0 ; . tools/build.sh >/dev/null 2>&1; resolve_channel_tag' </dev/null
resolve_channel_tag exit: 1

$ timeout 15 bash -c 'WEZ_RELEASE_API=http://127.0.0.1:0 ; . tools/build.sh >/dev/null 2>&1; download_release' </dev/null
[build] no TTY on stdin -> resolving the rolling 'nightly' channel (D-02 default)
[build] ERROR: could not resolve a nightly release tag — refusing to install an unverified asset
[build] ERROR: could not resolve WEZ_CHANNEL='nightly' to a release tag — aborting (no unverified install)
download_release exit: 1
```
`download_release()` aborts at the resolver check — BEFORE any URL is constructed,
any asset is fetched, and any `chmod +x` runs.

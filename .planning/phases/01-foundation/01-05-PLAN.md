<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| wezterm show-keys output -> parser | `wez keys` parses the textual `--lua` output of an external process; malformed or unexpected output must not crash or mis-classify silently |
| installed keybindings.lua -> keys command | keys reads a Lua file from the install location; a tampered file could skew classification |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | parsing untrusted show-keys text | mitigate | Parse defensively (validate each record has key+mods+action; skip+count malformed lines rather than executing them); never `load()`/`eval` the raw show-keys text as code |
| T-05-02 | Information Disclosure | --json output | accept | `wez keys --json` exposes only the user's own keybinding configuration — no secrets or PII; low-value local data |
| T-05-03 | Spoofing | mis-classification giving a false who-wins | mitigate | Classification is derived deterministically from the live effective table (ground truth for "who wins") per D-14, not from a static guess; conflicts are flagged from the effective table, not assumed |
| T-05-SC | Tampering | no package-manager installs | accept | This plan adds only first-party Lua; no npm/pip/cargo install occurs, so no Package Legitimacy Gate applies |
</threat_model>

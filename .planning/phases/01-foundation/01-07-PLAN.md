<objective>
Build shell completions (DIAG-05): generate zsh and bash completion scripts FROM the argparse spec
(`cli/spec.lua`, the single source of truth — D-16) so coverage grows automatically per phase; wire
`make install` to register them; and add a hidden `wez __complete` command that the generated shell
functions shell out to for dynamic values (future colors/scene names) so the static scripts never
need rewriting. `wez <Tab>` completes subcommands; `wez doctor`/`wez keys` flags complete.

Purpose: Phase 1 success criterion #5 — completions installed/registered for zsh and bash, subcommand
+ flag completion working. Depends on the stable argparse spec (Plan 01) and the installer (Plan 04)
for registration. Runs in Wave 4 (after Plan 04 completes in Wave 3).

Output: `wez completions <shell>` generator + `wez __complete` dynamic hook, the install-time
registration step added to `tools/setup.sh`, a generator unit test, and a repro proving `wez <Tab>`
completes. Designed cross-platform; verified on Linux (D-18).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| installer -> shell completion dirs / rc | the installer writes completion scripts and an fpath/source line into the user's shell config; malformed output could break shell startup |
| __complete output -> shell expansion | candidate values emitted by `wez __complete` are consumed by the shell during Tab expansion; unsanitized values could be mis-expanded |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | non-idempotent rc edit for completion loading | mitigate | The fpath/source registration line is guarded by a marker so re-install does not append duplicates; written under the same backup-before-edit discipline as Plan 04 |
| T-07-02 | Injection | `wez __complete` candidate values | mitigate | Candidates are newline-separated plain tokens drawn from a closed set (spec subcommands / known dynamic contexts); no shell metacharacters are emitted unquoted; the generated completion functions treat candidates as data, not code |
| T-07-03 | Elevation of Privilege | completion install location | mitigate | Completions are written to user-owned dirs (`~/.local/share/...`, `~/.zsh/...`); the install step contains zero `sudo` (grep-enforced) |
| T-07-SC | Tampering | no package-manager installs | accept | This plan adds only first-party Lua + a glue install step; no npm/pip/cargo install occurs, so no Package Legitimacy Gate applies |
</threat_model>

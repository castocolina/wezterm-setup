<objective>
Build the non-destructive installer (INST-01/02/03): inject a single sentinel-bounded managed block
into the user's `wezterm.lua` that wires `require('wezterm-setup').apply(config)` (D-17), back up the
original config with a timestamp first (INST-02), and handle re-install by prompting
override/restore/skip with a TTY or aborting non-zero with explicit-flag guidance without one (D-03).
Per D-01, bash (`tools/setup.sh`) is glue only — all sentinel parsing and the override/restore/skip
DECISION live in the Lua `wez` binary (`install_state.lua`). The `install-state` subcommand + its
flags are ALREADY registered in `cli/spec.lua` by Plan 01; this plan implements the command module
and does NOT edit spec.lua.

Purpose: Phase 1 success criterion #1 — clean install injects one managed block, timestamped backup,
nothing else touched; re-run prompts rather than silently overwriting. This depends on the WezTerm
bootstrap (Plan 02), the built `wez` binary (Plan 01), and the managed config tree (Plan 03).

Output: `tools/setup.sh` orchestrating bootstrap -> place config -> build/place wez -> back up ->
inject; the `install_state` Lua command owning detection + decision + injection; an R6 probe of real
`wezterm.lua` shapes; and a unit test for the sentinel parser. Designed cross-platform; verified on
Linux (D-18).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| installer -> user's wezterm.lua | the installer rewrites a file the user owns and depends on; a bug or mid-write failure could corrupt or lose the user's config |
| installer -> user shell rc | setup.sh edits `.bashrc`/`.zshrc` to register OSC 7 — a non-idempotent or malformed edit could break the user's shell startup |
| flags -> wez install-state | `--force`/`--restore`/`--skip` are user-supplied and drive destructive actions (override, restore) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | wezterm.lua corruption on write | mitigate | Always write a timestamped backup BEFORE any modification (INST-02); inject via a write-to-temp-then-atomic-rename so a failure leaves the original intact; the parser injects exactly one sentinel-bounded block |
| T-04-02 | Repudiation | silent overwrite of an existing managed block | mitigate | Re-install over a present block NEVER silently overwrites: TTY prompts override/restore/skip, no-TTY aborts non-zero with explicit-flag guidance (D-03) — the unit test enforces the non-zero no-TTY path |
| T-04-03 | Tampering | non-idempotent shell-rc edit | mitigate | The OSC 7 registration line is guarded by a sentinel/marker check so re-running does not append duplicates; edit shell rc via the same backup-before-write discipline |
| T-04-04 | Elevation of Privilege | install writes | mitigate | All writes target user paths (`~/.config`, `~/.local/bin`, `$HOME` rc files); setup.sh contains zero `sudo` (grep-enforced) |
| T-04-05 | Denial of Service | --restore reinstating a wrong/older backup | mitigate | `--restore` selects the NEWEST timestamped backup deterministically; the timestamp naming makes selection unambiguous and auditable |
| T-04-SC | Tampering | no package-manager installs | accept | This plan installs no npm/pip/cargo packages; the only fetched bytes (WezTerm tarball) are covered by Plan 02's threat model |
</threat_model>

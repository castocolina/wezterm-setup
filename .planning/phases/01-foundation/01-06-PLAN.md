<objective>
Build the install-lifecycle endpoints: `wez doctor` (DIAG-01) whose exit code is gated by
install-integrity CORE checks only (binary on PATH, sentinel block well-formed, config dir dofiles
cleanly, backup exists — FOUR gates), with completions-installed and live-session probes ADVISORY
(printed, never affecting exit 0) per D-15; and the granular uninstaller (INST-04/05) that removes
managed config, CLI, and sentinel block — independently controllable via
`--keep-config`/`--keep-backup`/`--keep-cli`. Per D-01 the removal/health DECISIONS live in the
Lua binary; `tools/uninstall.sh` is glue.

Purpose: Phase 1 success criterion #2 (granular uninstall) and the `wez doctor` half of criterion #4.
Depends on the CLI scaffold (Plan 01) and the installer (Plan 04) — doctor inspects what the
installer created; the uninstaller removes it.

Output: `wez doctor` + `wez uninstall-state` commands, `tools/uninstall.sh` glue wired to the
Makefile's KEEP_* env, unit tests, and a doctor repro capturing exit-0-on-healthy + non-zero-on-broken.
Designed cross-platform; verified on Linux (D-18).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| uninstaller -> user's wezterm.lua | block excision rewrites a user-owned file; a mis-scoped removal could delete user lines, not just the managed block |
| keep-flags -> uninstall_state | user-supplied flags decide what is destroyed vs preserved |
| doctor -> config dofile check | doctor loads the installed init.lua to test it dofiles cleanly — loading user-adjacent Lua must not have side effects |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | sentinel-block excision deleting user lines | mitigate | Excise EXACTLY the sentinel-bounded range using the shared install_state parser; the unit test asserts surrounding user lines are byte-identical after removal; write-to-temp-then-rename so a failure leaves the original intact |
| T-06-02 | Tampering | doctor dofile check executing arbitrary config | mitigate | Doctor loads the managed `wezterm-setup/init.lua` in a protected `pcall` to test it parses/loads cleanly; it does not execute user `wezterm.lua` top-level side effects |
| T-06-03 | Denial of Service | over-broad uninstall removing user data | mitigate | Removal targets only the four known managed paths/components; each gated by its keep-flag; no recursive removal of parent dirs the user owns (`~/.config/wezterm` itself is never removed, only the `wezterm-setup/` subtree) |
| T-06-04 | Elevation of Privilege | uninstall writes | mitigate | All removals target user paths; `tools/uninstall.sh` contains zero `sudo` (grep-enforced) |
| T-06-SC | Tampering | no package-manager installs | accept | This plan adds only first-party Lua + a glue shell script; no npm/pip/cargo install occurs, so no Package Legitimacy Gate applies |
</threat_model>

<objective>
Build the sudo-free WezTerm emulator bootstrap (INST-06): detect an existing adequate WezTerm and
reuse it untouched; otherwise download the generic `wezterm-<release>.Ubuntu<base>.tar.xz`, extract
it under `~/.local/opt/wezterm`, and symlink the `wezterm` binary into `~/.local/bin`. Offer
interactive version selection (rolling `nightly` + the last 5 dated GitHub releases) when a TTY is
present, and install a pinned known-good dated release (`20260604-145453`) when non-interactive.
Explicitly avoid AppImage (libfuse2) per the user's lived Pop!_OS failures.

Purpose: Phase 1 success criterion #6 — the install must bootstrap the emulator itself, sudo-free,
into a user path, reusing an existing install that meets the minimum version (D-04..D-08). This is
the chicken-and-egg layer: WezTerm must exist before any config or CLI behavior can be verified.

Output: `tools/bootstrap-wezterm.sh`, the `tools/lib/wezterm-release.sh` API helper, two R6 probes
recording the real tarball layout + releases-API shape, and a promoted repro doc proving the
sudo-free path works on Linux. macOS `.app` placement is designed-for but verified in the deferred
Mac pass (D-06, D-18).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network -> install host | the bootstrap downloads a `.tar.xz` (and queries the GitHub releases API) — untrusted bytes are extracted into the user's home and a binary is symlinked onto PATH |
| archive -> filesystem | tar extraction writes archive-controlled paths under `~/.local/opt/wezterm` — a malicious archive could attempt path traversal outside the target dir |
| existing install -> bootstrap | a pre-existing `wezterm` on PATH is trusted-as-reused; the bootstrap must not modify or escalate against it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | downloaded `.tar.xz` integrity | mitigate | Pin the release tag; verify the tarball against its published SHA-256 (or, if no checksum is published, record that gap in the probe and at minimum verify HTTPS + non-empty size + valid xz header) before extraction; abort non-zero on mismatch |
| T-02-02 | Tampering | tar extraction path traversal | mitigate | Extract into a freshly created per-release dir under `~/.local/opt/wezterm/<release>/`; use `tar` with a refusal of absolute/`..` members (e.g. `--no-absolute-names` / validate member paths); never extract over `$HOME` root |
| T-02-03 | Elevation of Privilege | install location | mitigate | All writes target user paths (`~/.local/opt`, `~/.local/bin`); the script contains zero `sudo` and never touches a system install (D-07) — grep-enforced in acceptance criteria |
| T-02-04 | Denial of Service | GitHub API rate limit / network outage | accept | On API failure the bootstrap degrades to the pinned `20260604-145453` default (D-08) rather than hard-failing; outage simply means the pinned release is used |
| T-02-05 | Spoofing | release source authenticity | mitigate | Fetch only from the official `github.com/wez/wezterm` releases host over HTTPS; the asset URL is constructed from the pinned/selected tag, never from arbitrary user input |
| T-02-SC | Tampering | no package-manager installs | accept | This plan installs no npm/pip/cargo packages; it downloads an official upstream release tarball (covered by T-02-01/05), so no Package Legitimacy Gate applies |
</threat_model>

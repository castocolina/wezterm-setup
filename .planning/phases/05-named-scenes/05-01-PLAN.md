<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| recipe-name argument -> filesystem path | `<name>` from `scene launch <name>` is interpolated into `<dir>/<name>.toml`; untrusted until guarded |
| TOML file content -> parser | a recipe file's bytes are untrusted input fed to the vendored decoder |
| upstream source -> vendored file | tinytoml.lua is third-party code baked into the shipped binary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering / Info Disclosure | `recipe.guard_name` (path traversal via `<name>`) | mitigate | guard_name rejects empty, `/`, and `..` (port of kitty `_guard_name`) BEFORE any I/O; verified by test assertions on `"a/b"`, `"../x"`, `""`. The resolved-parent==scenes-dir check is the IO-shell's job in 05-03 (defense in depth). |
| T-05-02 | DoS / crash | tinytoml parse of malformed/untrusted TOML | mitigate | `load_and_map` wraps `toml.parse` in `pcall` (tinytoml RAISES, Pitfall 1) and maps the error to the UI-SPEC "could not parse TOML at line <N>" copy — a crafted recipe yields exit-code error text, never a Lua traceback. tinytoml's own `max_filesize`/`max_nesting_depth` guards cap pathological inputs. |
| T-05-03 | Tampering (input validation) | recipe layout/color fields | mitigate | layout/color reuse the shipped `validate_layout`/`validate_color` enum checks — a recipe cannot inject an out-of-enum value; validate-before-emit means a bad recipe builds ZERO panes. |
| T-05-SC | Tampering (supply chain) | `cli/vendor/tinytoml.lua` | mitigate | Pin to v1.0.0 tag, record upstream URL + SHA-256 in a header, BLOCKING human review of the single-file diff (Task 1 checkpoint). TOML is pure data — no code eval; tinytoml has zero `require()` calls. |
| T-05-04 | Tampering (note only — not built here) | command execution in panes | accept | Recipe `command`/`cmd` values run in panes via the inherited Phase 4 path (05-03 delegates to `M.run_new`, which sends commands as DISTINCT trailing lines, never concatenated into escapes — T-04-02). A recipe file is the user's own data (same trust level as typing the command). No new execution surface in this plan. |
</threat_model>

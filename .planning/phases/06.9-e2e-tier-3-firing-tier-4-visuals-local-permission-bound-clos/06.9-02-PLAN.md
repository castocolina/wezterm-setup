## Round-1 review findings this revision fixes (see Review Dispositions Ledger at the bottom)
The prior version of this plan derived the uinput group directly from `stat -c '%G' /dev/uinput`
and passed it straight to `sudo usermod -aG` — on THIS box that device is `root:root`, so the prior
design would have run `sudo usermod -aG root "$(id -un)"`, a real privilege-escalation defect, not
a style nit. It also assumed Homebrew packages `ydotool`/`spectacle`/`grim`/`slurp`/`gnome-
screenshot` on Linux — live `brew info` during planning confirms NONE of those five formulas exist
for Homebrew-on-Linux (only `xdotool` and `imagemagick` do); a Linux host WITH Homebrew present
would therefore have been unable to provision itself at all for the other four. It omitted
ImageMagick from the install list even though Plan 04's comparator requires it, started `ydotoold`
immediately after a fresh group-add (before the new membership could possibly take effect in the
current session), and printed captured exit codes without ever asserting on them in `<verify>`.
All of these are fixed below with mechanisms verified live on this exact box during planning.

Purpose: Tier 3 Firing (Plan 01/03) and Tier 4 Visuals (Plan 04) both self-skip cleanly without
these tools, but a developer who actually wants the LIVE-ASSERTED path locally needs a single,
SAFE command that gets them there — and on THIS exact box (confirmed live during planning: the
invoking user is in groups `bazzite wheel`, NOT `input`; `/dev/uinput` is `root:root 660` with only
a systemd-udev `uaccess` seat-ACL tag — NOT a group grant — so blind group-membership logic would
either target `root` or silently fail to grant real access; no `ydotoold` is running; the session is
KDE Plasma on Wayland with `spectacle` already present; `imagemagick`'s `compare`/`convert` are
already present) the automation has genuine, verifiable, SAFE work to do.

<objective>
Ship the title half of the `wez tab` surface (TAB-03): `wez tab title "<text>"` standalone, the
combined `wez tab color <name> --title "<text>"`, and icon-name parity with `wez pane title`
(docker->🐳, rust->🦀; the existing icon-name map, lifted verbatim). All title resolution goes through a NEW shared module
`cli/lib/title.lua` — the Phase 2 icon map + `resolve_title` are LIFTED out of `pane.lua` so both
commands share one copy (D-03), not two.

Title writes are read-modify-write (D-01): `wez tab title api` keeps the tab's existing color
(`"blue:old"` -> `"blue:api"`); empty/`reset` clears the title keeping the color (`"blue:"`, D-04).
The combined `--title` form sets both halves in one `set-tab-title` write (`"blue:api"`).

Storage stays always-`"<color>:<title>"` (D-02); current-tab-only with the nil `tab_id` seam
unchanged (D-05).

Refactor constraint: `pane.lua` must keep behaving identically — re-export `ICONS`/`resolve_title`
from the shared lib so `pane_test.lua` and `M.run_title` see no behavioral change.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user title text -> `wezterm cli set-tab-title` argv | NEW in this plan: free-form title text (and icon-name tokens) now flow into the merged title string and out to `set-tab-title` |
| icon-name token -> glyph | A leading token is matched against the closed `ICONS` map; a non-match is treated as literal text — no lookup-table escape |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-0303-01 | Tampering | Command injection via free title text into `set-tab-title` | mitigate | The merged title is passed through the same `shquote` shell-quoting used in 03-02 before `os.execute`; title text is never concatenated unquoted; no `os.execute(string.format(...))` with raw bytes |
| T-0303-02 | Tampering | Title text containing terminal control / OSC bytes | mitigate | The value is delivered as a `set-tab-title` ARGUMENT (argv), not emitted as an OSC escape from this CLI; WezTerm stores it as the tab title string — there is no escape-context for the title to break out of (unlike Phase 2's OSC path, which base64-encodes). No raw escape emission occurs in tab.lua |
| T-0303-03 | Information Disclosure | Title text rendered to the tab bar | accept | Title originates from the local user's own command — same trust + disposition as Phase 2 pane title (already accepted) |
| — | (network / secrets / auth / privilege) | n/a | accept | None present in this phase — no sudo, no network, no credentials |
</threat_model>

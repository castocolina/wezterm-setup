<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `wez __complete <context>` -> shell Tab expansion | Output is consumed by the shell during completion; must be plain tokens, never shell code |
| spec/canonical tables -> completion candidates | Candidate sets are the closed color-name + icon-name tables, not user input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-0304-01 | Tampering | `__complete` emitting shell metacharacters interpreted during Tab expansion | mitigate | Reuse the existing T-07-02 guarantee: candidates are plain `[%w_-]` tokens from the closed color/icon tables; complete.lua emits only `token + "\n"`, no quoting/metachars (unchanged dispatch shape) |
| T-0304-02 | DoS | Completion hook hanging the shell | accept | `wez __complete` is a bounded table walk over the ~10 color names + the icon-name map; the generated scripts call it with `2>/dev/null` and tolerate empty output (a missing binary yields no candidates, never an error) |
| — | (network / secrets / auth / privilege) | n/a | accept | None present — completion is a local read-only table walk |
</threat_model>

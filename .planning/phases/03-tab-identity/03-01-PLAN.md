<objective>
Extend the Phase 2 tab-title formatter (`format-tab-title.lua`) to parse the `"<color>:<title>"`
prefix that `wez tab color`/`wez tab title` will write to `tab.tab_title` (Plan 03 of this phase),
and rewire its `format-tab-title` handler to apply the D-03a resolution precedence:

- **accent** = pane `WEZTERM_TAB_COLOR` -> else tab-prefix color -> else default profile
- **title** = pane `WEZTERM_TAB_TITLE` -> else tab-prefix title -> else `tab.active_pane.title`

The active-tab `●->` indicator + bold (TAB-05, already shipped) is preserved unchanged.

Purpose: this is the **central integration task** for Phase 3 (per `03-CONTEXT.md`) — without it,
`wez tab color`/`wez tab title` would write a value that never renders. TAB-02 (persistence across
pane switches) and TAB-04 (pane-color priority) are both observable ONLY through this formatter.

Output: `config/wezterm-setup/format-tab-title.lua` with a new pure `M.parse_tab_title(tab_title)`
helper and an updated handler body; `config/wezterm-setup/format-tab-title_test.lua` extended with
RED-then-GREEN fixture tests for the parse helper and the new precedence behavior.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WezTerm GUI -> format-tab-title handler | `tab.tab_title` is attacker-controllable only insofar as it was previously written by `wez tab title` (Plan 03) or set directly via `wezterm cli set-tab-title` by the local user — same trust level as the user's own shell |
| format-tab-title handler -> rendered tab bar | Output is `FormatItem[]` consumed by WezTerm's renderer, never shell/OSC — no escape-sequence injection surface here (that surface is in Plan 03's CLI write path) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | `M.parse_tab_title` on malformed `tab.tab_title` (e.g. only colons, very long strings) | mitigate | Pure string ops (`find`/`sub`) with nil/empty guards on both sides of the split; no pattern-injection risk since `:find(":", 1, true)` uses plain-text search (third arg `true`), not Lua patterns |
| T-03-02 | Information Disclosure | Resolved `title` rendered into tab bar | accept | Title text originates from the local user's own `wez tab title`/pane title — same trust boundary as Phase 2's pane title rendering, already accepted there |
| T-03-03 | Denial of Service | Handler called on every tab-bar redraw; an unbounded label could degrade rendering | accept | `M.format_label`/`wezterm.truncate_right` (existing, untouched) already bound output to `max_width`, applied identically regardless of which precedence branch supplied the title |
</threat_model>

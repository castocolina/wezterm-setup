# Phase 3 — UI Design Contract

> Visual and interaction contract for the WezTerm tab-bar surface. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.

---

## Surface Type

**This is a terminal tab-bar UI, not a web/app UI.** The entire visual surface is the array of
"format runs" (`{Background, Foreground, Attribute, Text}`) returned by the `format-tab-title`
event handler in `config/wezterm-setup/format-tab-title.lua`. There is no HTML, CSS, component
library, web typography scale, or spacing system. "Spacing" and "typography" below are
reinterpreted as terminal text attributes: indicator glyphs, leading/trailing space padding inside
a tab segment, byte/column truncation, and bold-vs-normal intensity.

Phase 3 does not introduce a new visual system — it **extends** the Phase 2 system
(`02-pane-identity/02-UI-SPEC.md`) by wiring the already-shipped `color:title` tab-prefix into the
formatter (D-03a) and verifying the resulting matrix (TAB-04, TAB-05). All values below are ported
verbatim from Phase 2 / the live `format-tab-title.lua` unless marked **NEW**.

## Spacing Scale

**Not applicable as a web spacing scale.** The only "spacing" in this surface is text padding
inside a tab-bar segment, fully determined by `format_label` and `build_runs`:

| Element | Value | Usage |
|---------|-------|-------|
| Active indicator | `" ●-> "` (leading space, glyph, arrow, trailing space — 5 chars) | Prefixed to the label only when `tab.is_active` |
| Inactive padding | `"  "` (two leading spaces) | Prefixed to the label for inactive tabs, visually aligns with the indicator's width |
| Label format | `"<n+1>: <title> "` (trailing space) | `format_label(index, title, max_width)` |
| Truncation limit | `max_width - 4` (byte-based fallback), then `wezterm.truncate_right(label, max(1, max_width - 4))` (column-aware) | Applied in the live handler after `format_label` |

Exceptions: none. This phase does not change `format_label`, the indicator string, or the
truncation arithmetic — D-03a only adds prefix-parsing *before* these functions run; their inputs
(resolved title, resolved profile) change, but their behavior does not.

---

## Typography

**Not applicable as a font/size scale.** The only "typography" distinction is bold vs. normal
intensity, applied via WezTerm `Attribute = { Intensity = ... }` runs:

| Role | Weight | Usage |
|------|--------|-------|
| Active indicator (` ●-> `) | Bold | `Foreground = #50fa7b` (green), always Bold regardless of accent |
| Active label text | Bold (inherited until `Intensity = "Normal"` run) | `Foreground = #ffffff` (white), overrides accent fg for legibility |
| Inactive label text | Normal | Uses `profile.fg` (resolved accent foreground, or default `#c0c0c0`) |

No new weights, sizes, or fonts are introduced. This table is unchanged from Phase 2.

## Color

### Accent profile table (locked, ported verbatim from `format-tab-title.lua` / Phase 2 UI-SPEC)

| Profile | Tab-bar `bg` | Tab-bar `fg` |
|---------|--------------|--------------|
| red | `#5f1e1e` | `#f0c8c8` |
| orange | `#5f3a1e` | `#f0d8c8` |
| yellow | `#5f5f1e` | `#f0f0c8` |
| green | `#1e5f2e` | `#c8f0d0` |
| teal | `#1e4f4a` | `#c8f0e8` |
| cyan | `#1e5f5f` | `#c8f0f0` |
| blue | `#1e3a5f` | `#c8ddf0` |
| navy | `#1a2040` | `#c8cce0` |
| purple | `#3f1e5f` | `#d8c8f0` |
| pink | `#5f1e4a` | `#f0c8e0` |

**Default profile** (no color set / unresolvable color): `bg = #333333`, `fg = #c0c0c0`.

> Locked: do not recompute, rebalance, or "improve" any of these 10 pairs or the default. Port
> verbatim. `resolve_profile` already validates: named profile (case-insensitive) → its pair; raw
> hex (`#rgb` / `#rrggbb`) → `{bg=hex, fg=DEFAULT_PROFILE.fg}`; nil/empty/unknown → default.

### Color role mapping (60/30/10 reinterpreted for a terminal tab bar)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | WezTerm theme background (unchanged, out of scope) | Pane content area |
| Secondary (30%) | `#333333` bg / `#c0c0c0` fg (default profile) | Tab-bar segments with no accent set — the baseline tab-bar chrome |
| Accent (10%) | One of the 10 named profile `{bg, fg}` pairs above | Reserved for: (1) the focused pane's OSC-11 background when a pane color is set (Phase 2, unchanged), AND (2) **NEW** — a tab's own tab-bar segment background+foreground when a tab-prefix color is set (TAB-01/TAB-02), for **both the active and inactive renderings of that tab** |
| Active-indicator override | `#50fa7b` (green, Bold) for ` ●-> `, `#ffffff` (white, Bold) for the label text | Reserved exclusively for the active tab's indicator + label — overrides `profile.fg` regardless of which accent (or default) the active tab carries |
| Destructive | not applicable | No destructive color exists in this surface — `reset`/clear are reversible (D-04), no red "delete" affordance |

**Accent reserved for:** the tab-bar segment background (`Background`) and foreground (`Foreground`,
inactive only) of the specific tab carrying that accent — via pane `WEZTERM_TAB_COLOR` (Phase 2,
highest priority) or tab-prefix color (Phase 3, D-03a, fallback). No other UI element may use these
10 colors.

### TAB-05 contrast-safety verification (NEW — locked verification result)

**Claim to verify:** the active tab must remain visually distinct from inactive tabs *regardless of
accent color* — i.e., the green/Bold indicator and white/Bold label must stay legible against every
possible `profile.bg`.

**Verification:** `build_runs` sets `Background = profile.bg` for **both** active and inactive
states — the active tab does **not** get a special background (the code comment at
`format-tab-title.lua:68` claiming "navy/profile bg" is **stale and should be corrected** in a
future cleanup pass; the actual behavior is `profile.bg` only). Differentiation between active and
inactive is therefore carried entirely by:

1. The ` ●-> ` indicator prefix (absent on inactive tabs, which get `"  "` instead)
2. `Foreground = #50fa7b` (green) + Bold on the indicator
3. `Foreground = #ffffff` (white) + Bold on the label text (inactive uses `profile.fg` + Normal)

All 10 profile `bg` values plus the default `#333333` fall in the dark-background range
(luminance roughly `0x1a`–`0x5f` per channel, per Phase 2's own contrast note). `#50fa7b` (green)
and `#ffffff` (white) against any of these 11 backgrounds (`#5f1e1e`, `#5f3a1e`, `#5f5f1e`,
`#1e5f2e`, `#1e4f4a`, `#1e5f5f`, `#1e3a5f`, `#1a2040`, `#3f1e5f`, `#5f1e4a`, `#333333`) yields
contrast ratios well above WCAG AA (4.5:1) — the lightest of these backgrounds (`#5f5f1e`,
`#5f3a1e`, `#5f1e4a` etc., luminance ≈ 0x5f per channel) is still far darker than `#50fa7b`/`#ffffff`.

**Result: TAB-05 is satisfied for all 10 accent profiles + default.** No accent profile may ever be
added with a `bg` luminance approaching `#50fa7b` or `#ffffff` (i.e., no light-background profile) —
this is the structural constraint that keeps TAB-05 true. Document this constraint if a future
phase proposes a light-themed profile.

## Rendering-states matrix (NEW — `color:title` prefix parsing, D-02/D-03a)

This is the **central new contract** for Phase 3. It defines how `tab.tab_title` (the stored
`"<color>:<title>"` string, written by `wez tab color`/`wez tab title` via D-01 read-modify-write)
must render once D-03a's prefix-parsing is added to `format-tab-title.lua`.

**Resolution precedence (locked, TAB-04):**

- **accent** = pane `WEZTERM_TAB_COLOR` (if set) → else tab-prefix color (parsed from
  `tab.tab_title`, split on first `:`) → else `DEFAULT_PROFILE` (`#333333`/`#c0c0c0`)
- **title** = pane `WEZTERM_TAB_TITLE` (if set) → else tab-prefix title (parsed from
  `tab.tab_title`) → else `tab.active_pane.title`

| Stored `tab.tab_title` | Parsed `(color, title)` | Rendered accent | Rendered title | Notes |
|---|---|---|---|---|
| `""` (empty / never set) | n/a — no colon found, empty string | `DEFAULT_PROFILE` (`#333333`/`#c0c0c0`) | `tab.active_pane.title` | Unchanged from current behavior — no prefix to parse |
| `"blue:api"` | `("blue", "api")` | `blue` profile (`#1e3a5f`/`#c8ddf0`) | `"api"` | Both set — TAB-01 + TAB-03 result |
| `":api"` | `("", "api")` | `DEFAULT_PROFILE` (`#333333`/`#c0c0c0`) — empty color resolves via `resolve_profile("")` | `"api"` | Title-only (D-02): accent removed via `wez tab color reset`, title kept |
| `"blue:"` | `("blue", "")` | `blue` profile (`#1e3a5f`/`#c8ddf0`) | falls through to `tab.active_pane.title` (tab-prefix title is empty, so resolution chain continues to pane title) | Color-only (D-02): title cleared via empty `wez tab title`, accent kept |
| `"blue"` (no colon — legacy/edge) | treated as a **bare color name** per the locked parse rule (`tab-title-format.md`) → `("blue", "")` | `blue` profile (`#1e3a5f`/`#c8ddf0`) | falls through to `tab.active_pane.title` | Same rendering as `"blue:"` — the no-colon bare-token IS the reason D-02 mandates "always write the colon" on every `wez tab` write, so user-written titles never collide with this rule |

**Pane-vs-tab priority (TAB-04) — both axes:**

| Pane var set? | Tab-prefix set? | Rendered accent | Rendered title |
|---|---|---|---|
| `WEZTERM_TAB_COLOR=green` | `tab.tab_title="blue:api"` | `green` (pane wins) | depends on title axis below |
| (none) | `tab.tab_title="blue:api"` | `blue` (tab-prefix) | depends on title axis |
| `WEZTERM_TAB_TITLE="custom"` | `tab.tab_title="blue:api"` | depends on color axis | `"custom"` (pane wins) |
| (none) | `tab.tab_title="blue:api"` | depends on color axis | `"api"` (tab-prefix) |
| (none) | `tab.tab_title=""` | `DEFAULT_PROFILE` | `tab.active_pane.title` |

The two axes (color, title) resolve **independently** — e.g. a pane can override only the color
(via `WEZTERM_TAB_COLOR`) while the tab-prefix title still shows, and vice versa. This is the
existing Phase 2 behavior for the title axis; D-03a extends the *same* independent-axis pattern to
the color axis using the tab-prefix as the new middle tier.

## Label/Title Format Contract

Unchanged from Phase 2 — D-03a does not alter `format_label` or the truncation pipeline, only the
*inputs* to it (resolved title, resolved profile):

- Structure: `"<index+1>: <resolved-title> "` (1-based tab index, colon-space separator, trailing
  space)
- Active tabs: prefixed with ` ●-> ` (green `#50fa7b`, Bold), label rendered in `#ffffff` Bold
- Inactive tabs: prefixed with `"  "` (two spaces), label rendered in `profile.fg` Normal weight
- Truncation: byte-fallback at `max_width - 4` inside `format_label`, then column-aware
  `wezterm.truncate_right(label, max(1, max_width - 4))` in the live handler — right-truncation
  only, no ellipsis character is added
- Icon-name title prefixes (D-03, e.g. `wez tab title docker`) expand to their glyph (🐳) as part
  of the resolved title string *before* `format_label` runs — the glyph is just additional text
  subject to the same truncation rules

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `wez tab color <name>` — set tab accent color; `wez tab color <name> --title "<text>"` — set color + title together; `wez tab title "<text>"` — set/replace title standalone |
| Empty state heading | not applicable — there is no "empty state" view; a tab with no color/title set renders with `DEFAULT_PROFILE` (`#333333`/`#c0c0c0`) and `tab.active_pane.title`, which IS the default appearance |
| Empty state body | not applicable (see above) |
| Error state | `error: unknown color "<input>"` to stderr, exit non-zero, **before** any `set-tab-title` write (validate-before-emit, D-06, mirrors Phase 2's `wez pane color` error wording exactly) |
| Destructive confirmation | none required — `wez tab color reset` (clears accent, keeps title) and empty `wez tab title` (clears title, keeps accent) are both reversible single-attribute clears (D-04); no confirmation prompt, matches Phase 2's `wez pane color reset` precedent |

## Decisions Made
- **Teardown mechanism:** background-launch the mux and capture its PID, then `kill` (then `kill -9`) + rmrf the scratch dir — this wezterm build exposes no `cli kill-server`, and the socket lives under the scratch XDG_RUNTIME_DIR so removing the dir leaves zero residue.
- **cwd contract (D-08):** the scratch config's `default_cwd` puts the mux's first (reused) pane in the launch dir, and the test `cd`s into the launch dir before invoking wez so the bash launcher's PWD-reset doesn't send split panes to the repo root.
- **User-vars:** verified empirically that `cli list --format json` on this build (20260614) returns no `user_vars` (null even after an explicit `SetUserVar` OSC), so the user-vars assertion soft-skips with a loud note and the no-leak interpreted-OSC proxy stands (exactly the plan's documented fallback).
- **Responsiveness target:** a freshly spawned shell pane, not the recipe's focused pane, because a focus pane may run an interactive program (`claude`, `$EDITOR`) that captures stdin — not a valid echo-liveness signal.

## Issues Encountered
- `wezterm cli spawn` without a pane/window context errors ("--pane-id was not specified and $WEZTERM_PANE is not set"); resolved by `spawn --window-id 0` for new tabs and `split-pane --pane-id <id>` for splits.
- The bash `dist/wez` launcher resets `PWD`, so passing `PWD=` had no effect on the panes' resolved cwd; resolved by `cd <launch dir> &&` before the invocation (works for both the bash dev launcher and the CI luastatic binary).
- The `ai` recipe's focused pane runs interactive `claude`; sending the marker there would never echo — handled by probing a dedicated fresh shell pane instead.

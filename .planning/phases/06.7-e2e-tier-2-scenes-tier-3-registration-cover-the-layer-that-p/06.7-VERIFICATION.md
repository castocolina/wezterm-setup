### Notable Observations (Info / non-blocking)

1. **Tier 3 "Cmd-family AND Ctrl-family" wording vs. per-OS reality (documented deviation D-06).** The ROADMAP goal and PRD A.3 phrase the registration contract as "each action has ≥1 Cmd-family AND ≥1 Ctrl-family chord." The implementation deliberately asserts only the families that *legitimately register on the running OS* (Plan 03 / D-06): on Linux `SpawnTab=CTRL` (the managed SUPER+T is WM-grabbed and absent from the effective table), `RotatePanes=ALT-only`, `SendString=CTRL-only`; macOS `SpawnTab` includes SUPER. This is the correct, only-technically-possible behavior on Linux (a blanket "Cmd AND Ctrl" would false-fail on every Linux host), is recorded as a finding in `platform.chord_families.note`, the plans, PATTERNS, and the SUMMARYs, and — critically — the CORE intent of the requirement (the check that catches the dead new-tab binding) is fully achieved and independently proven by `make e2e-prove`. Treated as VERIFIED-with-deviation, not a gap. If you want this deviation recorded against the literal PRD wording for the milestone audit trail, add an override (suggestion below).

2. **README Tier 3 "Needs: live mux" is slightly inaccurate (cosmetic).** README line 41 lists Tier 3 Registration's dependency as "live mux", and line 74 calls it "live-mux registration contracts." Tier 3 registration actually needs only a *runnable wezterm* for `show-keys --lua` (it is deterministic and spins no mux — it gates on `wezterm_runnable`, not `mux.probe`). Documentation-only wart; the test behaves correctly.

3. **Tier 2 LIVE-ASSERTED reason string reads oddly (cosmetic).** The Tier 2 banner prints `LIVE-ASSERTED (wezterm-mux-server unavailable (headless mux not resolvable))` — the reason string was phrased skip-only, so it contradicts the LIVE-ASSERTED marker it rides on. Tier 3 fixed this with path-neutral phrasing ("needs a runnable wezterm..."). No functional impact; the tier did live-assert and ran real assertions.

These three are info-level and do not block the goal. Items 2 and 3 are candidate one-line polish for a future docs pass.

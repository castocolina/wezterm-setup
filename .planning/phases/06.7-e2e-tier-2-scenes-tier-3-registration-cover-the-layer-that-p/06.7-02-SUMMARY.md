## Decisions Made
- **Precondition via split, not spawn:** `mux.spawn_pane` opens a NEW tab; only `mux.split_pane(first_pane_id)` keeps both panes in ONE tab, which is what `decide_materialization` needs to see (>=2 panes in the current tab) to choose new-tab mode.
- **New-tab identification:** snapshot the pre-launch tab id set, then the `new_tab_id` helper returns the single tab id absent from that snapshot (nil if ambiguous/none). This is robust against the originating tab and any later probe tab, rather than guessing an id.
- **Inherited mechanism choices:** the user-vars-or-no-leak-proxy branch and the fresh-shell-pane responsiveness probe mirror the reuse driver exactly (same wezterm build 20260614, same constraints: no user_vars in cli list, interactive focus panes).

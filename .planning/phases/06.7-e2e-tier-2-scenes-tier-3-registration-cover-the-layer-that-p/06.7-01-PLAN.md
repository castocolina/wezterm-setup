<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test -> wezterm-mux-server / wezterm cli | test-controlled scratch paths + recipe names cross into spawned process command lines |
| spawned mux -> user's real WezTerm GUI session | the launcher (scene.lua) uses bare `wezterm cli`; without isolation it could target the live session |
| `wezterm cli list` JSON -> Lua | untrusted process output decoded into the assertion layer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06.7-01 | Tampering | mux.lua / scene_reuse shell-outs to wezterm + wezterm-mux-server | mitigate | quote EVERY interpolated scratch path/recipe name via harness.shquote; never concat unescaped scratch paths into command lines |
| T-06.7-02 | Denial of Service | spawned headless wezterm-mux-server (orphan process / dirty tree) | mitigate | per-case `mux.teardown` (kill-server + rmrf) in a pcall/finally so a failed assertion still tears down; spin is bounded-poll, never a bare sleep |
| T-06.7-03 | Information Disclosure / wrong-target | bare `wezterm cli` in scene.lua connecting to the user's live session | mitigate | drive launch ONLY against the scratch mux (scratch XDG_RUNTIME_DIR/HOME/WEZTERM_CONFIG_FILE + isolated socket) so no spawn/assertion touches the real `~/.config/wezterm` or running GUI |
| T-06.7-04 | Tampering | `wezterm cli list --format json` output parsed in Lua | mitigate | decode via the existing JSON decoder; never `load()`/eval the output |
| T-06.7-SC | Tampering | npm/pip/cargo installs | accept | no package-manager installs in this phase; wezterm / wezterm-mux-server are pre-existing system binaries, not fetched |
</threat_model>

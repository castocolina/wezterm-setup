## Tier 3 Linux catch-scope (reconciles the Plan 04 break harness — READ THIS)
Under D-06 the test asserts only the families that LEGITIMATELY register on the running OS, so on
Linux Tier 3 can only catch a dead-binding regression in a family that actually appears in the Linux
effective table. Concretely on this box's live `wezterm show-keys --lua`:
  - SpawnTab registers ONLY under CTRL-family chords (`T/CTRL`, `T/SHIFT|CTRL`, `t/SHIFT|CTRL` — the
    Ctrl+Shift+T default fold). The managed SUPER+T (keybindings.lua:85) does NOT appear, and
    `disabled_defaults` (~line 140) disables ONLY the SUPER+T default. So a regression that removes
    SUPER+T is INVISIBLE to Tier 3 on Linux; a regression that drops the CTRL-family new-tab chord
    (the Ctrl+Shift+T default) IS caught.
  - RotatePanes registers ONLY under ALT (ours; WezTerm ships no default), and word-nav SendString
    ONLY under CTRL — config-only families with no masking default.
The Plan 04 break harness MUST therefore drop SpawnTab's CTRL-family chord (not the SUPER one) so the
injected loss is provably asserted here. Plan 03 (expected family = CTRL for SpawnTab on Linux) and
Plan 04 (inject a CTRL-family new-tab loss) target the SAME registration.
</objective>

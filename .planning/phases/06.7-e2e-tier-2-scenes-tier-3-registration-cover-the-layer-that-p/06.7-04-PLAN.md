<objective>
Ship the permanent, per-bug "break harness" (D-09): `tools/run-e2e-prove.sh` + a `make e2e-prove`
target that injects each known regression ONE AT A TIME — (1) the scene escape-leak in
`cli/commands/scene.lua` (caught by Tier 2's no-leak check) and (2) the dead new-tab binding in
`config/wezterm-setup/keybindings.lua` (caught by Tier 3's registration check) — runs the battery,
asserts it FAILS for that injection, then reverts. It is re-runnable living proof the battery has
teeth, and it MUST leave the tree clean even on abort. Depends on Tier 2 (Plans 01/02) and Tier 3
(Plan 03) existing, so it runs in Wave 3.

Purpose: a green battery is only trustworthy if it actually fails on the two real regression classes
that motivated it; this harness demonstrates that, per-bug, on demand.
Output: `tools/run-e2e-prove.sh` (bash-3.2-safe) + a `make e2e-prove` target.

## Regression B must target the SAME registration Tier 3 asserts (reconciles Plan 03 — READ THIS)
On Linux SpawnTab registers ONLY under CTRL-family chords (the Ctrl+Shift+T default fold: live
show-keys shows `T/CTRL`, `T/SHIFT|CTRL`, `t/SHIFT|CTRL`). The managed SUPER+T (keybindings.lua:85)
does NOT appear in the Linux effective table, and `disabled_defaults` (~line 140) already disables
only the SUPER+T default. So removing the SUPER+T row drops NOTHING Tier 3 asserts on Linux — the
battery would stay green and the dead-new-tab proof would structurally fail on the only available
platform. Regression B therefore drops the CTRL-FAMILY new-tab chord (Plan 03 sets `linux.SpawnTab =
{CTRL}` as the asserted family), so the injected loss is provably caught here. Plan 03 (asserts
SpawnTab/CTRL on Linux) and Plan 04 (drops SpawnTab/CTRL) target the SAME registration.
</objective>

## How each regression is proven

**Regression A — scene escape-leak (Tier 2, D-05).** `inject_scene` neutralizes the self-erasing `CLEAR_SCROLLBACK_AND_VIEWPORT` wipe in `cli/commands/scene.lua`, so the typed `printf '...'` setup line's echo survives in the pane viewport. Tier 2's no-leak check (`get-text` finds `printf '`) flips to FAIL. The battery runs with `WEZ_BIN=./dist/wez` (the dev launcher execs the in-repo `cli/` sources), so the edit is exercised directly with no config dance. Proven here because the headless `wezterm-mux-server` resolves as a sibling of the `wezterm` binary; where no mux is resolvable it emits a loud `PROVE SKIP`.

**Regression B — dead new-tab binding (Tier 3, D-06).** `inject_keys` adds a `DisableDefaultAssignment` for `{ key = "t", mods = "CTRL|SHIFT" }` to `M.disabled_defaults` in `config/wezterm-setup/keybindings.lua`. A single entry removes ALL three folded CTRL-family SpawnTab chords (`T/CTRL`, `T/SHIFT|CTRL`, `t/SHIFT|CTRL`) from the effective table. The managed SUPER+T is WM-shadowed and absent on Linux, so this CTRL-family disable is what flips Tier 3's `linux.SpawnTab = {CTRL}` assertion.

**Live-config verification (in-script):** post-injection the harness runs `wezterm show-keys --lua` and asserts NO SpawnTab chord registers under any CTRL-family mods before running the battery — exactly the loss Tier 3 asserts.

## Live-config mechanism (key design choice)

Tier 3's live layer reads `wezterm show-keys --lua`, which parses the INSTALLED config (`~/.config/wezterm/wezterm-setup/keybindings.lua`) — a COPY of the repo source, not a symlink. The harness therefore injects the canonical repo source AND cp-syncs it to the installed copy so the live wezterm sees the regression, backing up the installed copy first and restoring it byte-for-byte afterward.

This deliberately AVOIDS exporting `WEZTERM_CONFIG_FILE` to a scratch config: a prior implementation did so, which made Tier 1's `wez doctor` report a non-standard install and FAIL spuriously on every prove run (it is non-zero whenever `WEZTERM_CONFIG_FILE` is set), polluting the proof. The cp-sync approach leaves Tier 1 untouched, so only the catching tier fails under each injection. The project memory note ("config-layer edits need cp-sync to ~/.config") confirms this is the established mechanism.

## Tree-clean / safety guarantees (T-06.7-20)

- **Pre-flight refusal:** refuses to run (exit 1, no injection) if either repo target is already dirty (staged or unstaged), so it never clobbers a real in-progress edit. Verified: a manual edit is left intact.
- **Reverting EXIT trap:** `trap revert_all EXIT` git-restores both repo targets and restores the installed copy from backup, so an abort/error/Ctrl-C still leaves a clean tree. Verified: killing the harness mid-run left the tree clean and the installed config restored.
- **Belt-and-braces:** a final `git diff --quiet` on both repo targets fails loudly if anything is somehow still dirty.

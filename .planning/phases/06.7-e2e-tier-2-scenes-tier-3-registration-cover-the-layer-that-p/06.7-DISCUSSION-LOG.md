## Tier 2 — CI posture & flake policy

| Option | Description | Selected |
|--------|-------------|----------|
| Deterministic state-polling, no retries | Poll until expected state, bounded timeout, no retries — flake = bug | |
| Polling + bounded retries | State-polling plus a small-N retry safety net | ✓ |
| Fixed generous sleeps | Tuned fixed timeouts/sleeps — simplest, classic flake source | |

**User's choice:** Polling + bounded retries (D-01/D-02)
**Notes:** Pairs with the fresh-mux-per-case isolation below for a belt-and-braces reliability posture. Retries kept small + logged so an intermittent real hang stays visible.

## Tier 2 — Live-test reliability mechanics (isolation / cleanup / probe / leak)

| Option | Description | Selected |
|--------|-------------|----------|
| Throwaway tab + marker sweep | Dedicated tagged tab per case; teardown closes it + marker sweep | |
| Kill individual panes per case | Track + kill each spawned pane id | |
| Fresh mux-server per case | Dedicated `wezterm-mux-server` per case — max isolation | ✓ |

**User's choice:** Fresh `wezterm-mux-server` per case (D-03)
**Notes:** Accepted defaults — no-hang probe = UUID-marker echo within bounded timeout (D-04); "leak" = literal `printf '` / raw octal / `quote>` in `get-text` (D-05).

## Tier 3 — Registration design

| Option | Description | Selected |
|--------|-------------|----------|
| Platform-expected families (platform.lua) | Assert the families actually expected on the running platform | ✓ |
| Require both families everywhere | Cmd + Ctrl on every platform — false-fails on Linux | |
| Require any chord per action | ≥1 chord of any family — misses a dropped Cmd-only variant | |

**User's choice:** Platform-expected families from `platform.lua` (D-06)
**Notes:** Curated action list = PRD verbatim, cross-checked against `keybindings.lua` (D-07); divergence is surfaced as a finding, not silently dropped. Parse stays string-only via `showkeys.lua` (D-08).

## Deliberate-regression demo shape

| Option | Description | Selected |
|--------|-------------|----------|
| Permanent per-bug break harness | Re-runnable target injects each regression separately, asserts FAIL, reverts | ✓ |
| One-time demo in SUMMARY | Manual break → capture FAIL → revert; no artifact | |
| Permanent combined demo | One target injecting both bugs at once | |

**User's choice:** Permanent per-bug break harness, e.g. `make e2e-prove` (D-09)
**Notes:** Per-bug so each check's teeth are shown independently; must leave the tree clean on exit (revert even on failure).

### Gaps Summary

The phase nails the **authoring** half of its goal: the README is a clean 77-line progressive-disclosure
hub, the five focused docs/ pages are well-scoped per D-11/D-12/D-13, the stale Status/Development
sections and the entire migration/repro corpus are gone, the doctor nugget is salvaged, and there is
zero scope creep beyond the D-10-sanctioned trivial fixes. The shipped docs are, by manual spot-check,
currently accurate.

But the phase's **load-bearing guarantee** — the durable D-08/D-09 drift-check that is supposed to be
the machine-verified accuracy evidence for "every documented command/flag/keybinding/scene field exists
in source" — is broken. `tests/docs_drift_test.lua` silently os.exits in the middle of its scan (when it
feeds a documented `wez pane --help` through `argparse:pparse`, which terminates the process with exit 0),
so it is recorded as PASS by `run-tests.sh` while having validated only README.md and the first ~34
checks of cli.md. The entire docs/scenes.md D-13 reference, docs/keybindings.md, docs/install.md, the
TOML scene-field / layout / color validation, and — critically — the `fires_on_bad_reference` firing-proof
block all NEVER execute (confirmed: 0 `fires:` lines and 0 tally lines in the real run; a planted bad
reference does not flip the exit code). The accuracy of today's docs is therefore real but **incidental
and undefended**: a future drift in any unscanned doc would pass silently.

This is the one deliverable the phase was built around, so it gates the phase. The fix is small and
local (prevent `pparse` from terminating the host process — detect `--help`/`-h` or run flag validation
in a sandboxed child — then confirm the firing proof runs and a planted bad token flips `make test` red),
plus adding docs/troubleshooting.md to the governed set. No re-authoring of the docs is needed.

## CRITICAL

- **C-1 — Plan 01 `<behavior>` `source_chords()` uses `require("keybindings").kb.keys`, which is nil.**
  `config/wezterm-setup/keybindings.lua` returns the module table `M` directly; `keys` is a
  top-level field (`M.keys`). There is no nested `.kb` sub-table, so `require("keybindings").kb`
  is `nil` and `....kb.keys` raises a runtime error — `source_chords()` would never run.
  **Fix:** in the Plan 01 `<behavior>` `source_chords()` clause, use
  `local kb = require("keybindings"); kb.keys` (or `require("keybindings").keys`).
  The same plan's `<action>` block already uses the correct `require("keybindings").keys`, and the
  `key_links` header's `via: require keybindings -> kb.keys` is correct shorthand — only the
  `<behavior>` bullet is wrong, and it is the authoritative spec the executor implements.

## HIGH

  The exported normalizers are `M.canonicalize_key` (keys.lua:77) and `M.norm_mods` (keys.lua:49).

  → nil, as PATTERNS.md's "copy norm_key/norm_mods from keys.lua:29-46" note could mislead).

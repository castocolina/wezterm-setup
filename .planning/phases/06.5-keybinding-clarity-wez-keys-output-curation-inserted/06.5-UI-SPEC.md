# Phase 06.5 — UI Design Contract

> Visual and interaction contract for the `wez keys` terminal output. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Medium: TERMINAL CLI (stdout text), NOT web/GUI.** The "UI" is the human-readable text `wez keys` prints to a terminal. There is no HTML/CSS/component library/web font/browser. Every classic UI-SPEC dimension is re-mapped to the monospace-terminal medium below; dimensions that are genuinely N/A for a CLI say so explicitly rather than inventing web content.
>
> All visual/interaction decisions are **LOCKED** in `06.5-CONTEXT.md` (D-01..D-10). This file FORMALIZES them into precise, testable contracts (exact column widths, header strings, glyphs, SGR codes, footnote text, empty-state behavior). The planner's TDD fixtures and the e2e assertions key off the literals here.

| Property | Value |

The only additions are: action-first column order (D-07), a per-action chord list, ANSI-red conflict styling (D-06), a platform-label transform (D-03/D-04), and a static Linux footnote (D-03).

## Spacing Scale (terminal adaptation)

> Web pixel spacing is N/A. In a monospace CLI, "spacing" = blank lines, left indentation, and inter-column padding measured in **character cells**. The scale below is the locked set of cell/line values; the renderer MUST use only these.

| Token | Value | Usage |
|-------|-------|-------|
| Row indent | 2 cells (`"  "`) | Left padding of every binding/conflict row (matches current `keys.lua:274`) |
| Inter-column gap | 1 cell (minimum) | Min gap between the action column and the chord column, and between chord and label; supplied by the `%-Ns` field width + a literal space |
| Section blank line | 1 blank line | Exactly one blank line BEFORE each `== Section ==` header (leading `\n` in the header format) |
| Footnote blank line | 1 blank line | Exactly one blank line separating the managed section's last row from the footnote block |
| Trailing newline | 1 newline | Output ends with exactly one trailing `\n` (current behavior, `keys.lua:284`) |

**Column widths (LOCKED — fixture-asserted literals):**

| Column | Field spec | Width | Rationale |
|--------|-----------|-------|-----------|
| Action | `%-26s` | 26 cells | Longest real action token is `ClearScreenAndScrollback` (24) + 2 cells breathing room. Action is column 1 under D-07 (action-centric). |
| Chord list | `%-30s` | 30 cells | Holds the grouped multi-chord string (e.g. `CTRL+SHIFT+k, SUPER+k`); widest real case ≈ `CTRL+SHIFT+PageDown` plus a second chord. Left-justified. |
| Label | `%s` (trailing, no pad) | flush | `[setup]` / `[default]` / `[user]` — last column, no trailing pad so rows have no trailing whitespace. |

Row format string (managed/defaults rows): `"  %-26s %-30s %s\n"` → `action`, `chord_list`, `[label]`.

**Exceptions:** Conflict-summary rows use a distinct format (see Copywriting → Conflicts). No other spacing exceptions.

**Hard rules:**
- No trailing whitespace on any line (the final column is unpadded `%s`).
- Indentation is spaces only, never tabs (tab width is terminal-dependent and would break the monospace grid).
- Column widths are fixed literals, NOT computed from the data at runtime — fixtures assert exact byte output.

## Typography (terminal adaptation)

> Web font sizes/weights/line-heights are N/A — a terminal has one monospace cell size set by the user. The "typographic" contract here is **case, separators, and token shape** within the fixed grid.

| Role | Contract | Source |
|------|----------|--------|
| Section header | `== {label} ==` on its own line, preceded by one blank line. Exact label strings in Copywriting. | D-05/D-06, `keys.lua:271` |
| Action token | Verbatim action name as it appears in the effective table (e.g. `CloseCurrentTab`), no case transform. | D-07 |
| Chord token | Canonical form: lowercase single-letter base key + ALL modifiers explicit, joined by `+`. Letter case NEVER carries meaning. e.g. `ALT+SHIFT+x`, `CTRL+SHIFT+w`. | D-01/D-02/D-08 |
| Modifier order | Fixed: **SUPER > CTRL > ALT > SHIFT** (most-significant first). Replaces the current alphabetical `table.sort` in `norm_mods`. | D-02, `keys.lua:51` |
| Separator | `+` between modifier/key tokens in the human table. (`--json` keeps native `|` as data.) | D-02 |
| Multi-chord join | `, ` (comma + single space) between distinct chords on an action row, reliable-chord-first. | D-07 |
| Label token | Lowercase, square-bracketed: `[setup]`, `[default]`, `[user]`. | existing `keys.lua:274` |

**Canonicalization rule (LOCKED, letter-only — D-01):**
- IF the base key matches `^%a$` (single ASCII letter) AND is uppercase AND mods does NOT contain `SHIFT` → lowercase the key token AND add explicit `SHIFT` to mods.
- Digits, symbols, and named keys (`PageUp`, `LeftArrow`, `+`, `1`) pass through UNCHANGED — they do NOT fold (RESEARCH Pitfall 2). The guard `^%a$` is mandatory.

**Case-variant collapse (D-08):** Two records that canonicalize to the same `(key, mods)` render as ONE row (the old `CTRL+SHIFT+z` / `CTRL+SHIFT+Z` twins collapse automatically once D-01 lowercases). No separate dedupe heuristic.

## Color (terminal adaptation — ANSI SGR, decorative-only)

> Web hex palettes / 60-30-10 surface splits are N/A — there is no canvas to fill. Terminal "color" = ANSI SGR escape codes applied to text, and it is **decorative-only**: it MUST degrade to a fully legible plain-text output. Color is NEVER the sole carrier of meaning.

| Role | Value | Usage |
|------|-------|-------|
| Default text | no SGR (terminal default fg) | All managed + defaults rows, all headers except the conflict summary. The 60/30 "dominant surface" concept maps to: the overwhelming majority of output is uncolored. |
| Conflict accent (10%) | `\27[31m` … `\27[0m` (SGR 31 = red, reset 0) | RESERVED for: (a) the inline conflicting binding row in its section, and (b) the `== Conflicts (who-wins) ==` summary rows. Nothing else is ever colored. |
| Conflict summary header | `\27[1;31m` … `\27[0m` (bold red) | The `== Conflicts (who-wins) ==` header line only. |

**Accent reserved for:** conflict rows (inline) and the conflict summary section ONLY. Never colorize action names elsewhere, labels, the managed footnote, or non-conflict rows.

**Color is decorative-only / never the sole signal (accessibility — color-blind + NO_COLOR):**
- Every red row is ALSO marked with a text glyph: a leading `! ` prefix AND a trailing `[CONFLICT]` token (see Copywriting). Stripping all color leaves the conflict fully identifiable from text alone.
- The exact glyph is ASCII `!` (U+0021) — not a Unicode symbol — so it renders in any terminal/font.

**Emission gate (IO-shell decision — D-06, RESEARCH Code Example):** emit SGR only when ALL hold:
1. NOT `--json` (JSON output is NEVER colorized — SGR bytes must never enter the JSON document), AND
2. `os.getenv("NO_COLOR")` is unset (respect the NO_COLOR convention), AND
3. stdout is a TTY (`io.popen("test -t 1")` check) — never colorize piped/redirected output.

If any gate fails → emit the identical text WITHOUT SGR (the `!`/`[CONFLICT]` markers still carry the meaning).

**ANSI-injection safety (RESEARCH Security Domain):** SGR wraps ONLY our own fixed fields (the row we format). The untrusted `action` string from `show-keys` is opaque text and MUST NOT be passed through an SGR builder that could interpret embedded escapes. Color the fixed columns, not the raw action payload.

**Second semantic color:** none. Red is the only SGR color in this phase. No green/yellow/etc.

## Layout & Section Ordering (LOCKED — D-05/D-07)

The default `wez keys` (no flags) output, top to bottom:

```
== wezterm-setup (managed) ==
  <action>                   <chord-list>                  [setup]
  ...                        (categories Tabs/Panes/Navigation/Font/Other
                              preserved as the inner grouping under each section)

  Note: On Linux the Super key is often claimed by your desktop
  (e.g. Pop!_OS grabs Super+W / Super+K), so Super chords may not
  reach WezTerm. The Ctrl+Shift chord listed first is the reliable one.

== WezTerm defaults ==
  <action>                   <chord-list>                  [default]
  ...

== Conflicts (who-wins) ==           (RED — shown ONLY if conflicts exist)
  ! <chord>                  <reason>                      [CONFLICT]
  ...
```

**Ordering contract:**
- Managed (`setup`) section ALWAYS first; WezTerm-defaults (`default` + `user`) section after. Nothing hidden. No `--managed`/`--mine` filter flag exists (D-05).
- Within each section, the existing category order is preserved as the inner grouping: **Tabs → Panes → Navigation → Font → Other** (RESEARCH Open Q2 resolution: nest action-rows inside categories, don't flatten them).
- Within an action row, chords are ordered **reliable-chord-first**: the layout-stable `CTRL+SHIFT+…` chord precedes a `SUPER+…` chord on Linux (D-07, ties to the Super-grab concern). Under `--platform macos`, Super/Cmd is reliable and may lead.

## Platform Label (LOCKED — D-03/D-04)

| Platform value | `SUPER` renders as | Source |
|----------------|--------------------|--------|
| `linux` (default on Linux host) | `Super` | D-03 |
| `macos` (default on macOS host) | `Cmd` | D-03 |
| `all` | inline annotation per chord | D-04, RESEARCH Open Q1 |

- `--platform linux|macos|all` flag (NEW, registered in `cli/spec.lua` alongside `--json`); default = host OS. Only the SUPER **label** changes — no row is added/removed by platform.
- `--platform all` layout = **inline annotation** (NOT extra columns), to preserve the single-row action-centric layout: a Super-bearing chord renders as `Cmd+w (macOS) / Super+w (Linux)`. Non-Super chords are platform-invariant and render once with no annotation.
- The platform map is a PURE string transform; the host-OS default detection lives in the IO shell.

**Footnote (LOCKED placement + wording — D-03):** rendered ONCE, immediately after the managed section's last row, separated by one blank line, indented 2 cells, NOT colored:

```
  Note: On Linux the Super key is often claimed by your desktop
  (e.g. Pop!_OS grabs Super+W / Super+K), so Super chords may not
  reach WezTerm. The Ctrl+Shift chord listed first is the reliable one.
```

- Show this footnote when the rendered platform is `linux` or `all` (i.e. any time a `Super` label can appear on Linux). Omit it under `--platform macos`.
- The renderer does NOT attempt runtime Super-grab detection (not reliably possible — RESEARCH Pitfall 1); the footnote is the honest static fallback.

## Copywriting Contract

> "Primary CTA" / "empty state" / "error state" map to: section header labels, the no-data / no-conflicts behavior, and the missing-session / not-installed messages.

| Element | Copy (exact literal) |
|---------|----------------------|
| Managed section header | `== wezterm-setup (managed) ==` |
| Defaults section header | `== WezTerm defaults ==` |
| Conflict summary header | `== Conflicts (who-wins) ==` (bold-red on a TTY) |
| Conflict inline marker | leading `! ` prefix + trailing `[CONFLICT]` token on the conflicting row |
| Conflict reason tokens | `overridden` / `action-mismatch` (existing `classify` reasons, `keys.lua:146/156`) — rendered verbatim in the conflict row's reason column |
| Category sub-headers | `Tabs`, `Panes`, `Navigation`, `Font`, `Other` (inner grouping; existing tokens) |
| Linux Super footnote | the 3-line `Note:` block above (verbatim) |
| Label tokens | `[setup]`, `[default]`, `[user]` |

**Empty / no-data states:**
- **No conflicts** → OMIT the entire `== Conflicts (who-wins) ==` section (header + rows). Do NOT print an empty conflict header or a "no conflicts" line. (Matches current `if #conflicts > 0` guard, `keys.lua:277`.) This is the locked empty-state behavior.
- **A section with zero rows** → omit that section header entirely (don't print `== WezTerm defaults ==` with nothing under it). Mirrors the existing "drop empty seeded groups" behavior (`keys.lua:188`).

**Error states (existing copy, preserved — `keys.lua:240/253`):**
- No live WezTerm session: stderr `wez keys: cannot read live key table (…)` + `wez keys: a running WezTerm session is required.`, exit 1.
- `keybindings.lua` not installed: stderr `wez keys: keybindings.lua not found at <path> (…); run the installer (install-state) first.`, then classify with empty "ours" (every binding falls to default/user). Non-fatal.

**Destructive actions:** none. `wez keys` is read-only (it spawns `wezterm show-keys` and reads the installed config); it mutates nothing and needs no confirmation prompt. (The separate `keybindings.lua` reconcile in D-09/D-10 is a code edit verified by a live firing probe, not a runtime UI action — no user-facing confirmation surface.)

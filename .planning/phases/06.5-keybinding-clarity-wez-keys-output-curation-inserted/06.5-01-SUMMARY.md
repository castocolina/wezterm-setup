# Phase 06.5 Plan 01: Pure ANSI SGR Red Helper Summary

Pure ANSI SGR text-color helper (`cli/lib/ansi.lua`) emitting the byte-exact red
(`\27[31m`…`\27[0m`) and bold-red (`\27[1;31m`…`\27[0m`) sequences the conflict
renderer (Plan 02) and the e2e lane (Plan 04) assert against — a side-effect-free
SGR builder kept distinct from the OSC-background `color.lua` (D-06).

## What Was Built

- **`cli/lib/ansi.lua`** — pure module (`local M = {}` … `return M`) with a PURITY
  banner mirroring `color.lua`'s (no `require("wezterm")`, no `io.*`, no
  `os.execute`, no `os.getenv`). Exports:
  - `M.red(s)` → `"\27[31m" .. tostring(s) .. "\27[0m"` (SGR 31 / reset 0)
  - `M.bold_red(s)` → `"\27[1;31m" .. tostring(s) .. "\27[0m"` (SGR 1;31 / reset 0)
  Each wraps its argument VERBATIM — the helper never inspects or escapes its
  input; ANSI-injection safety is the caller's responsibility (T-06.5-01). No
  reuse of `color.lua` (OSC background is a distinct concern — overloading it is
  a locked anti-pattern).
- **`cli/lib/ansi_test.lua`** — byte-exact RED-first fixtures mirroring the
  `cli/lib/title_test.lua` header (require + `check`/`eq` + run-from-repo-root
  comment + `os.exit(fail == 0 and 0 or 1)` footer): red/bold-red wrap, empty-input
  round-trip (red + bold_red), and verbatim-wrap of `"a b!"`.

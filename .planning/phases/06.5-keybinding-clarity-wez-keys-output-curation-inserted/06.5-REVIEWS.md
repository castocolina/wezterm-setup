## HIGH-1 — Plan 04 D-09 firing probe verifies against `wezterm cli list`, which cannot prove a chord fired (affects 06.5-04)

**Where:** `06.5-04-PLAN.md` Task 2 (the `checkpoint:human-verify` D-09 firing probe), the readback/observe step using `wezterm cli list --format json`.

**Problem:** `wezterm cli list --format json` reports pane/tab/window state — it does NOT report which keybinding fired or whether pressing e.g. `Ctrl+Shift+K` actually triggered `ClearScreenAndScrollback`. The probe's stated verification artifact is logically disconnected from the claim being verified (the reconciled chord fires its action). As written a "pass" proves nothing about firing.

**Required fix (06.5-04):** Specify a concrete OBSERVABLE that proves each reconciled chord fired. For each chord, give a before/after the human (or harness) can confirm — e.g. for clear: `wezterm cli send-text` a known sentinel string into the pane, press the chord, then confirm via screenshot/`import`+Read (the project's live-GUI recipe) that the scrollback/sentinel is gone; for close-pane/close-tab: confirm the pane/tab count dropped in `wezterm cli list` BEFORE vs AFTER pressing the chord (here `cli list` is a legitimate before/after delta, not a fire-detector on its own). Tie each chord in the reconciled set to its observable effect. Keep the `checkpoint:human-verify` gate.

## HIGH-4 — Plan 02 TTY detection is underspecified and may duplicate an existing helper (affects 06.5-02)

**Where:** `06.5-02-PLAN.md` Task 2 GREEN — the color gate (TTY ∧ ¬NO_COLOR ∧ ¬--json).

**Problem:** The TTY check (`io.popen("test -t 1")`-style) does not specify (a) the exact condition tested on the return (exit status vs empty output), nor (b) the behavior when `io.popen` returns nil on restricted systems (fail-closed to no-color is the safe default, but it must be stated). **Required fix (06.5-02):** (a) State whether any existing module already does TTY detection; reuse it if so. (b) If new, specify the exact success condition and that a nil/failed `io.popen` fails closed (no color). (c) Confirm the check lives in the IO shell, not in `ansi.lua`.

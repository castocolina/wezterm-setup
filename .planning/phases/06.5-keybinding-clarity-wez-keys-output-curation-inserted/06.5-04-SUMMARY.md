# Phase 06.5 Plan 04: Live `wez keys` e2e + D-09 firing probe Summary

**Guarded display-capable-aware live e2e for the curated `wez keys` output
(three-group ordering / dedupe / unambiguous render / json-no-ANSI / platform-all
annotation / red-conflict NO_COLOR degradation), LIVE-ASSERTED 19 passed / 0 failed
on DISPLAY=:1; plus the D-09 firing probe operator-verified PASSED — all three
reconciled chords fire on a live Pop!_OS session by their concrete observable effect.**

## Accomplishments

- **Guarded live e2e lane (Task 1).** `tests/integration/keys_integration_test.lua`
  drives the real `wez keys` binary against the live `wezterm show-keys` mux and
  asserts, end-to-end on the live stdout:
  - **(1) three-group ordering (D-05/D-12)** — `== Managed (overrides) ==` →
    `== Our additions ==` → `== WezTerm defaults ==` with byte-offset order
    `Managed < Additions < Defaults`, and our `ALT+SHIFT` ergonomic keys landing
    under `== Our additions ==` tagged `[added]`;
  - **(2) unambiguous render (D-01/D-02)** — no chord renders an uppercase-letter
    base; every letter chord is lowercase + explicit `SHIFT`;
  - **(3) twin/action dedupe (D-07/D-08)** — a dual-chord action renders ONE
    `, `-joined row; the reconciled `CTRL+SHIFT+K`/`CTRL+SHIFT+W` uppercase twins
    never appear as standalone rows;
  - **(4) `--json`** carries no `\27[` SGR byte and stays jq-valid (dkjson + `jq .`);
  - **(5) `--platform all`** inline-annotates a Super chord (`(macOS)` AND `(Linux)`);
  - **(6) red-conflict degradation (D-06)** — under `NO_COLOR=1` zero SGR bytes,
    `! `/`[CONFLICT]` text markers retained when a conflict is present.
- **Display-capable-aware skip gate (MEDIUM-2).** The whole-lane skip fires ONLY
  when the host is NOT display-capable (DISPLAY non-empty AND `wezterm cli list
  --format json` returns a `pane_id`). On a display-capable host the live
  assertions MUST execute and the run prints a `LIVE-ASSERTED` marker — a `SKIPPED`
  there is a FAILURE, so a hollow/skipped pass is impossible. Per-assertion
  `soft_skip` (logged, not failing) handles checks the live session lacks data for.
- **Live-asserted, not skipped (ae9ff53 update).** Re-run against the reloaded
  session (after the 06.5-05 three-group renderer fix) the lane prints
  `keys_integration_test: LIVE-ASSERTED (DISPLAY=:1, mux reachable)` and reports
  **19 passed / 0 failed** — the live assertions actually EXECUTED, no skip.
- **D-09 firing probe PASSED (Task 2 — blocking-human gate).** On 2026-06-19 the
  operator confirmed on their live Pop!_OS WezTerm session that the three reconciled
  chords fire by their concrete observable effect:
  - `Ctrl+Shift+K` → ClearScreenAndScrollback: scrollback cleared;
  - `Ctrl+Shift+W` → CloseCurrentTab: tab count dropped by one;
  - `Alt+Shift+X`  → CloseCurrentPane: pane count dropped by one.
  No fallback to the uppercase-char form was needed. This closes the deferred-from-
  Plan-03 firing verification (T-06.5-05) and satisfies the project's
  "verify before declaring done" gate.

## Decisions Made

- **The live e2e ordering assertion was repointed to the three-group headers
  (ae9ff53).** When authored (00e4462), the lane targeted the original single
  `== wezterm-setup (managed) ==` header. The 06.5-05 renderer rewrite replaced that
  with three sections; the code-review follow-up updated the e2e to assert
  `Managed < Additions < Defaults` byte-offset ordering live, so the lane verifies
  the shipped renderer rather than a stale header. This is the correct cross-plan
  convergence (Plan 04 e2e validates the Plan 05 fix on the live session).
- **D-09 firing is a human gate, not a headless assertion.** The e2e lane proves
  render/ordering/json/platform/conflict; the *firing* of the actual chords needs a
  live GUI session and a recorded manual repro (a `checkpoint:human-verify`, never
  auto-approved). The operator verdict ("approved / they fire") is the acceptance.

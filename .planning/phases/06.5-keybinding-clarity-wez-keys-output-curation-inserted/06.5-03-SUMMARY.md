# Phase 06.5 Plan 03: Collapse Lower+Upper Key Twins to D-10 Single Entries Summary

Reconciled `keybindings.lua` to the D-10 canonical declaration form: dropped the redundant uppercase `mapped("K")` / `mapped("W")` `Ctrl|Shift` twins, leaving one lowercase-base + explicit-SHIFT entry per action, mirroring the already-working single-entry close-pane row — with `init.lua resolve_action` untouched and in lockstep.

## What Was Built

- **Removed the two uppercase TWIN rows** in `config/wezterm-setup/keybindings.lua`:
  - `mapped("K")` `CTRL|SHIFT` `ClearScreenAndScrollback` (was line 81)
  - `mapped("W")` `CTRL|SHIFT` `CloseCurrentTab` (was line 92)
- **Kept exactly one `CTRL|SHIFT` entry per action** — the lowercase `mapped("k")` / `mapped("w")` form — alongside their unchanged `SUPER` siblings (a genuine second chord per action, not a case twin).
- **Rewrote the now-stale comment blocks** (clear-screen + close-tab) that justified declaring "both lowercase AND uppercase": they now state the D-10 single-entry rationale — WezTerm folds Shift into the produced uppercase char and collapses the lower+upper pair to ONE effective row, so the second entry was always redundant; this mirrors the working single-entry close-pane binding (`mapped("x")` `ALT|SHIFT`).
- **Left untouched:** every `action.type` value, `M.disabled_defaults`, and `M.key_map_preference = "Mapped"`.

## How It Works

The edit is restricted to `key`/`mods` rows plus the comment block. No `action.type` was added or removed anywhere in the file, so `init.lua resolve_action` — a closed switch that `error()`s on an unknown `action.type` (Pitfall 3) — needs no change and stays exhaustive. The lockstep is proven headlessly by `tests/config/apply_test.lua`, which loads `init.lua` under a `wezterm` stub via `package.preload` and runs `apply()` → `resolve_action` over every reconciled binding without raising.

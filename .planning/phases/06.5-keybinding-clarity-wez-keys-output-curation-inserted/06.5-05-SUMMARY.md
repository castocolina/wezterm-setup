# Phase 06.5 Plan 05: `wez keys` grouping + conflict-noise fix Summary

**Fixed the root-cause cross-source identity bug (id_of now canonicalizes) so our
ALT+SHIFT letter bindings classify as ours under a new three-group render
(Managed overrides / Our additions / WezTerm defaults), and reduced Conflicts to
true non-Super-absent bindings only — Super chords and present overrides no longer
generate noise.**

## Accomplishments

- **Root-cause matching fix (D-14-fix).** `id_of` now strips `mapped:`, folds the
  letter base to lowercase, makes the implicit SHIFT explicit, and normalizes mods
  BEFORE building the identity token. Our `mapped:x` + `ALT|SHIFT` and the live
  `X` + `ALT` now share one identity (`x\0ALT|SHIFT`). Digits, symbols, and named
  keys (`1`/`=`/`PageUp`) still pass through unchanged. This single fix removes both
  the `[user]` misclassification of our letter chords and the false `overridden`
  conflicts that double-counted them.
- **Three-group classify + render (D-12).** `classify` now tags every effective
  entry with a `group` derived purely from `(in_ours, in_base)`:
  `managed` (ours ∩ base, label `setup`), `additions` (ours ∖ base, label `added`),
  `defaults` (not ours, label `default`/`user`). `run()` renders three sections in
  the fixed order **`== Managed (overrides) ==` → `== Our additions ==` →
  `== WezTerm defaults ==`** via the existing `render_section`/`group_by_action`
  path (category sub-ordering preserved); empty sections print no header.
- **True-conflict-only filter (D-13).** A conflict is recorded ONLY for a NON-Super
  binding genuinely absent from the effective table after canonical matching.
  Present bindings (ours wins) emit no row; all Super-bearing chords are suppressed
  (Linux WM grabs them — the reliable Ctrl+Shift sibling is what matters). The old
  `action-mismatch` branch and its dead `actions_equivalent` helper were removed.
- **`--json` parity.** `build_json` consumes the same filtered conflicts; output
  stays jq-valid with zero SGR bytes.

### Auto-fixed Issues

**1. [Rule 1 - Bug] Removed the now-dead `actions_equivalent` helper**
- **Found during:** Task 1 GREEN (classify rewrite).
- **Issue:** D-13 drops the action-mismatch conflict branch entirely (presence =
  ours wins). That left `actions_equivalent` (a local function) with zero callers —
  an unused-local that would trip luacheck and confuse future readers.
- **Fix:** deleted the helper and replaced its doc-comment with a D-13 note that
  who-wins is decided purely by presence in the effective table.
- **Files modified:** `cli/commands/keys.lua`
- **Verification:** full suite green; no unused-local warning.
- **Committed in:** `b2e51ed` (Task 1 GREEN commit).

**2. [Rule 1 - Bug] Rewrote my own RED `s7` assertion (cross-section greedy match)**
- **Found during:** Task 1 GREEN (first run after the render change).
- **Issue:** the RED `s7` pattern `out:find("Super.-%[CONFLICT%]")` used Lua `.`
  (which matches newlines), so it greedily spanned from a legitimate `Super` chord
  in the WezTerm-defaults section all the way down to the `[CONFLICT]` token in the
  Conflicts section — a self-inflicted false positive, not a real Super-in-conflict.
- **Fix:** rewrote `s7` to scan each rendered line and assert that no line bearing
  `[CONFLICT]` also bears `Super`. This is the precise intent (no conflict ROW
  carries Super) and passes against the correctly-filtered output.
- **Files modified:** `cli/commands/keys_test.lua`
- **Verification:** `s7` green; live `./dist/wez keys` Conflicts section shows only
  `CTRL+Tab` / `CTRL+SHIFT+Tab` (zero Super rows).
- **Committed in:** `b2e51ed` (Task 1 GREEN commit).

**3. [Rule 3 - Blocking] Updated existing `f1`/`f3` to the renamed managed header**
- **Found during:** Task 1 GREEN.
- **Issue:** the three-group render renames the single `== wezterm-setup (managed) ==`

- **Fix:** repointed `f1`/`f3` to the new `== Managed %(overrides%) ==` pattern

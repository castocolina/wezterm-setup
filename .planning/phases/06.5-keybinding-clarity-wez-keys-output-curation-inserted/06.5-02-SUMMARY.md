# Phase 06.5 Plan 02: Curated-First `wez keys` Renderer Summary

Rewrote the `wez keys` renderer so output is unambiguous, de-noised, and
curated-first: a single canonical lowercase-base chord with all modifiers explicit
in fixed `SUPER>CTRL>ALT>SHIFT` order, one row per action with chords grouped
reliable-chord-first (CTRL+SHIFT before the WM-grab-prone Super), the managed
section printed before WezTerm defaults with a Linux Super footnote, and ANSI-red
conflict rows gated behind a fail-closed TTY probe — all new logic in the PURE,
fixture-testable layer of `cli/commands/keys.lua`, plus a new `--platform`
selector guarded by a `cli/spec_test.lua` regression assertion.

## What Was Built

**Pure transforms (no io/os/wezterm — the autonomous gate), `cli/commands/keys.lua`:**

- `canonicalize_key(key, mods)` — D-01 letter-only fold. An uppercase single ASCII
  letter (`^%a$`) with no SHIFT folds to lowercase + explicit SHIFT
  (`ALT+X` -> `ALT+SHIFT+x`); digits, symbols, and named keys (`1`, `=`, `PageUp`)
  pass through unchanged (RESEARCH Pitfall 2).
- `render_mods(mods)` — D-02 human modifier form: fixed rank
  `{SUPER=1,CTRL=2,ALT=3,SHIFT=4}`, `+`-joined; `NONE`/empty -> `""` (no leading `+`).
  Separate from `norm_mods` (kept pipe-joined as the classify identity).
- `platform_label(key, mods, platform)` — D-03/D-04: `SUPER` -> `Super` (linux) /
  `Cmd` (macos); under `all` a Super-bearing chord renders the inline annotation
  `Cmd+w (macOS) / Super+w (Linux)`; non-Super chords are platform-invariant.
- `group_by_action(entries)` — D-07 action-centric grouping + D-08 case collapse.
  One row per action; the `, `-joined chord list is ordered by the PINNED reliability
  rank (rank 1 = CTRL∧SHIFT∧¬SUPER, rank 2 = SUPER, rank 3 = other), ties broken by
  original insertion index. Canonicalize runs first, so case-variant twins fold to one.
- `color_enabled(args, no_color, is_tty)` — D-06 pure gate (`not json AND not
  no_color AND is_tty`).
- `conflict_row(chord, reason)` — the pinned `"  ! %-16s %-30s %s\n"` literal with
  arg1=chord, arg2=reason (`overridden`/`action-mismatch`), arg3=the literal `[CONFLICT]`.
- `norm_mods` / `id_of` EXPORTED on the PIPE form (unchanged identity for classify).

**IO shell (`run()`), `cli/commands/keys.lua`:**

- Host-OS platform default via `uname -s` (Darwin -> macos, else linux); `--platform`
  overrides.
- `stdout_is_tty()` — a NEW fail-closed TTY probe authored fresh in the IO shell
  (HIGH-4: `ansi.lua`/`color.lua` are pure and have no TTY detector, and none exists
  repo-wide). `io.popen("test -t 1; echo $?")`; TTY-true IFF output is exactly `"0\n"`.
  Any spawn/read/close failure or other output -> false (no stray SGR on a restricted host).
- Curated-first sectioning: `== wezterm-setup (managed) ==` (setup) first, then
  `== WezTerm defaults ==` (default+user); empty sections omitted; rows via
  `"  %-26s %-30s %s\n"`. The 3-line Linux Super `Note:` footnote prints once after
  the managed section on linux/all only.
- Conflicts (only when present): `== Conflicts (who-wins) ==` bold-red header +
  `conflict_row` lines red — wrapping ONLY our fixed columns, never the opaque
  `action` string (T-06.5-02). `--json` path is untouched and SGR-free.
- Test-injection seams (`_ours`, `_color_force`, `_effective_text`, `_baseline_text`)
  so the renderer is headless-deterministic.

**Spec + fixtures:**

- `cli/spec.lua`: `keys:option("--platform", ...)` registered (linux|macos|all).
- `cli/spec_test.lua`: three registration assertions (`--platform all/linux/macos`).
- `tests/fixtures/showkeys_effective.lua` + `showkeys_baseline.lua`: LIVE-captured
  `wezterm show-keys --lua` / `wezterm -n show-keys --lua` samples (committed text,
  never eval'd; driven through `showkeys.parse`).
- `cli/commands/keys_test.lua`: 49 assertions pinning every D-01/D-02/D-05/D-06/
  D-07/D-08 + platform-label case against the UI-SPEC literals, including the pinned
  D-07 dual-chord row (`CTRL+SHIFT+w, SUPER+w`) and the pinned conflict-row format.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `keys_test.lua` could not load `dkjson` under the runner**
- **Found during:** Task 2 GREEN (first `make test`).
- **Issue:** the `--json` run() path requires the vendored `dkjson`, but the test
  did not bootstrap `package.path`; under `tools/run-tests.sh` (which sets no
  `LUA_PATH`) the `require("dkjson")` failed.
- **Fix:** added the `package.path` bootstrap (`repo_root .. "/?.lua"` +
  `cli/vendor/?.lua`) at the top of `keys_test.lua` and anchored the fixture reads
  to `repo_root` — mirrors the existing `cli/commands/scene_test.lua` idiom.
- **Files modified:** `cli/commands/keys_test.lua`
- **Commit:** `96966dd`

**2. [Rule 1 - Bug] RED test's synthetic `_ours` produced no `setup` label**
- **Found during:** Task 2 GREEN (f1/f3/f4 failed — no managed section).
- **Issue:** the initial synthetic `_ours` (`w`/`CTRL|SHIFT`) matched no entry in
  the live effective fixture (which reports `W`/`CTRL` for CloseCurrentTab post-fold),
  so nothing classified as `setup` and the managed section was empty.
- **Fix:** swapped the synthetic match to `Enter`/`ALT` (`ToggleFullScreen`), which
  is present in BOTH the effective AND baseline fixtures, so it deterministically
  classifies as `setup` (ours ∩ baseline ∩ effective) and guarantees a non-empty
  managed section + the footnote; kept the `zzz_absent` entry as the guaranteed
  `overridden` conflict.
- **Files modified:** `cli/commands/keys_test.lua`
- **Commit:** `96966dd`

**3. [Rule 1 - Bug] PLAN's pinned conflict-row example miscounted `%-16s` padding**
- **Found during:** Task 1 RED (the literal verification).
- **Issue:** the PLAN pins both the format string `"  ! %-16s %-30s %s"` AND a
  fully-substituted example `"  ! CTRL+SHIFT+w      overridden ... [CONFLICT]\n"`
  with SIX spaces after the 12-char chord; `%-16s` of a 12-char string yields FOUR
  trailing spaces. The format string is the authoritative contract.
- **Fix:** corrected the test's `cr1` assertion to the true byte form
  (`"  ! CTRL+SHIFT+w     overridden ... [CONFLICT]\n"`, 4 spaces). `conflict_row`
  uses `:format(...)` so it always agrees with the format string, never the
  miscounted prose example.
- **Files modified:** `cli/commands/keys_test.lua`
- **Commit:** `b3899d9` (RED) / asserted green in `96966dd`

These test refinements landed in the GREEN commit because they were necessary to
make the single RED suite correctly executable under `tools/run-tests.sh`; the
RED suite still failed RED (the new exports were absent) before GREEN.

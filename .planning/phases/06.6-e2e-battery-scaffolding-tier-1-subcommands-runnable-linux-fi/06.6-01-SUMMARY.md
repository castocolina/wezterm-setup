# Phase 06.6 Plan 01: E2E Battery Scaffolding Summary

Shared, bash-3.2-safe E2E battery scaffold — hoisted Lua harness, loud self-skip
gate, pure platform-parity table, a `make e2e` orchestrator, and the `run-tests.sh`
exclusion that keeps the battery out of `make test` — so Tier 1 (Plan 02/03) and
06.7–06.9 plug in instead of re-declaring the harness.

## What was built

**Task 1 — Lua scaffold (`57e0569`)**
- `tests/e2e/lib/harness.lua` returns table `M` with the MODULE-LEVEL helpers the
  Tier 1 files consume: `check` (TAP-ish `ok`/`FAIL` against a module-level
  pass/fail tally), `run_capture` / `run_capture_all` (the repo's only exit-capture
  idiom — `io.popen` + `local ok,_,code = p:close()`), `shquote`, `scratch_dir`
  (unique TMPDIR/tmp dir per run), `footer` (prints `\n%d passed, %d failed`,
  returns `0` iff `failed==0`), and `WEZ` (`$WEZ_BIN` or `wez`). An optional
  `M.new()` returns a fresh instance owning its own counters for the rare
  counter-isolation case.
- `tests/e2e/lib/skip.lua` returns `require_env` (whole-tier env opt-in →
  loud `SKIP` + exit 0; 06.9 plugs in `WEZ_E2E_INPUT` / `WEZ_E2E_VISUAL`),
  `require_tool` (dependency predicate → `SKIPPED (reason=…)` + exit 0 when absent,
  `LIVE-ASSERTED (…)` + return when present — a skip on a capable host is
  impossible to hide), and `soft_skip` (per-assertion, no exit). Tier 1 needs
  neither gate; it exists so 06.7–06.9 plug in.
- `tests/e2e/platform.lua` is a PURE module (no wezterm dep, loads under plain
  lua5.4) with `platform_os()` / `platform_arch()` mirroring `tools/lib/platform.sh`
  (Darwin→macos, Linux→linux, arm64→aarch64, amd64→x86_64; lowercased via Lua
  `string.lower`, never `${var^^}`) plus an `expectations` table encoding the PRD
  A.5 parity rows (Lua resolution, SUPER key, macOS bundle siblings, bash 3.2 vs 5,
  input tools) — the single source later tiers assert parity against.

**Task 2 — orchestrator + boundary (`b6a68fb`)**
- `tools/run-e2e.sh`: `set -u` (no `set -e` over the loop so one bad file can't
  abort the batch — T-06.6-02), repo-root from `${BASH_SOURCE[0]}`, `LUA_BIN` guard
  (exit 127), bash-3.2-safe `while IFS= read -r … done < <(find … | sort)`
  discovery (no `mapfile`/`readarray`/`declare -A`/`${var^^}`), per-file PASS/FAIL
  aggregate (empty discovery = clean exit 0), `--setup` arm printing the macOS
  permission placeholder (installs nothing). Defaults `WEZ_BIN=./dist/wez` when
  present+unset; CI overrides it. Clean under `bash -n` and `shellcheck -x`.
- `tools/run-tests.sh`: extended discovery to keep the e2e battery out of
  `make test` — a `! -name '*_e2e_test.lua'` find predicate AND a
  `*_e2e_test.lua | tests/e2e/*` case arm (belt-and-braces), with an updated
  discovery comment. No new bash-4 construct (the pre-existing line-50 `mapfile`
  is unchanged; `readarray`/`declare -A` count stays 0).
- `Makefile`: `.PHONY` extended with `e2e e2e-setup`; two help lines; two
  `@`-prefixed thin-glue targets dispatching into `run-e2e.sh` (no decision logic).
- `tests/e2e/README.md`: tier matrix (T1 this phase; T2/T3-reg 06.7; T3-fire/T4
  06.9 with M/B classes), `WEZ_BIN` override note, per-platform tool/permission
  placeholder, manual visual-baseline approval placeholder, and the `make e2e` vs
  `make test` boundary note.

## Deviations from Plan

None — plan executed exactly as written. Two comment rewordings (not behavior
changes) were needed so the acceptance-criteria literal greps stay clean:
`platform.lua` and `harness.lua` comments avoided the exact `require("wezterm")` /
`os.setenv` tokens, and `run-e2e.sh` comments avoided the exact
`mapfile`/`readarray`/`declare -A` tokens. The code was always pure / bash-3.2-safe;
only prose mentioning the forbidden constructs was reworded.

## Known Stubs

`make e2e-setup` intentionally installs nothing this phase — it prints the macOS
permission placeholder only. Documented as intentional in `tests/e2e/README.md`
and the script header; the actual tool install + macOS Accessibility/Screen-Recording
grant flow is owned by Phase 06.9. This is a planned, not accidental, placeholder
(per CONTEXT: "make e2e-setup → tooling: THIS phase installs nothing").

## Notes for downstream

- Tier 1 files (Plan 02/03) live under `tests/e2e/tier1/` and are TWO levels below
  `tests/`, so their `package.path` bootstrap needs `repo_root = this_dir .. "/../../.."`
  (three `..`), and they require the harness via the e2e lib path.
- The harness module-level tally is process-global; a single test file that requires
  `harness` once and calls `h.check(...)` throughout, ending with `os.exit(h.footer())`,
  is the intended shape. Use `M.new()` only when a file needs isolated counters.

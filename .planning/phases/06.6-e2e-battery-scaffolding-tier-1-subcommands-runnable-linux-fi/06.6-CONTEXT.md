<decisions>
## Implementation Decisions

Everything below is a **locked decision** from the PRD (treat as binding) unless marked
"Claude's Discretion".

### Architecture / Runtime
- **Assertion logic in Lua** — identical across platforms, zero runtime deps, consistent with the
  existing `tests/` + `tools/run-tests.sh` harness and the `WEZTERM_INTEGRATION` self-skip gate.
- **Orchestration that must shell out is bash-3.2-safe** — macOS ships bash 3.2, Linux ships
  bash 5 (a portability footgun this project already guards against). No bash-4+ constructs
  (no `mapfile`/`readarray`, no associative arrays, no `${var^^}`).
- **Zero *runtime* dependencies** — any test-only tools are installed via `make e2e-setup`, never
  required by `wez` itself.
- **Each tier emits TAP-ish `ok`/`FAIL` lines** matching the current harness so results aggregate
  through `run-tests.sh` / CI uniformly.

### Gating model
- `make e2e` runs everything available locally; permission-bound tiers self-skip when their
  dependency is absent (env opt-ins `WEZ_E2E_INPUT=1` / `WEZ_E2E_VISUAL=1` belong to 06.9, but
  the **self-skip gate mechanism is built here** so later tiers plug into it).
- **Self-skip must be loud and logged — never a silent pass, never a hang.**

### Tier 1 — Subcommands (all MUST-PASS, headless)
Per PRD Appendix A.1, assert exit code + output shape + emitted-byte well-formedness for:
- `wez version` → exit 0, prints a version string.
- `wez doctor` → exit 0, gate lines present.
- `wez keys` → exit 0, non-empty; `wez keys --json` → exit 0 + **valid parseable JSON**.
- `wez completions bash` / `wez completions zsh` → exit 0, non-empty completion script.
- `wez seed-scenes` (scratch `WEZTERM_SETUP_DIR`) → copies the 3 recipes (copy-if-absent; re-run
  keeps existing).
- `wez scene new …` → emits the expected recipe/spec text (no mux needed).
- `wez pane color|title|icon` and `wez tab color|title|icon` (+ reset/clear) → exit 0 and
  **capture the emitted OSC bytes**, asserting well-formed (OSC-1337 / OSC-11, correct terminators).
- `wez install-state` / `wez uninstall` → idempotency + non-interactive contracts (managed-block
  install/override, `--force`/`--skip`, exit codes; uninstall idempotent when binary absent;
  `dist/wez` fallback).
- `wez update` → exit 0 / clean no-op when already latest (smoke).
- **Edge cases:** unknown scene name → exit 1; empty recipes dir → exit 2; path-traversal
  (`../../etc/passwd`) → exit 1; non-interactive reinstall over an existing block → `--force`
  default, exit 0.

<specifics>
## Specific Ideas

- **OSC delivery model (from the handoff — critical for the byte assertions):** user-vars reach
  the terminal as PROGRAM OUTPUT, not shell input. `wez pane color` writes OSC to its own stdout.
  Tier 1 captures that stdout and asserts the OSC is well-formed — this is the same stdout
  mechanism the reuse-pane scene styling (06.7) depends on, so getting the byte contract right
  here de-risks 06.7.
- **Self-skip + integration gate already exist in spirit:** `WEZTERM_INTEGRATION` gates the live
  integration tests today; the new self-skip gate generalizes that pattern (mux/tool/permission
  absent → skip loudly).
- **Dev launcher vs static binary:** Tier 1 should run against the project's `wez` (dev launcher
  `dist/wez` execs repo `cli/` sources live; the luastatic binary is the shipped form). Decide
  which the battery targets (likely `dist/wez` for local dev + the built binary in CI).
- **Recipe inventory** = `scenes/{ai,dev,docker}.toml` (3 recipes) — `seed-scenes` copies these.

</specifics>

# Phase 06.6 Plan 04: Migration & Reset Reuse (Cherry-Pick the Verified Fixes) Summary

The Migration & Reset reuse step: the 4 independently-verified `archive/phase-7-macos`
fixes brought forward onto main, each test-first and re-verified on Linux. Three install/
uninstall fixes (dev-launcher Lua 5.4 resolution, idempotent uninstall, non-interactive
reinstall + dist/wez uninstall fallback) cherry-picked clean with their tests; the
Plan-04-owned post-resolver Tier 1 contract (`install_resolver_e2e_test.lua`) added; the
two Plan-02-staged install_cycle assertions flipped to their post-7e72bf5 end-state; and
the macOS-only keys-siblings fix re-shaped (per user decision) into an OS-detect +
skip-gated Tier 1 test plus a tracked Phase-7 deferral — rather than importing the deferred
macOS installer it depends on. `make test` (34 files) + `make e2e` (6 files) exit 0;
`./dist/wez version` works.

## Deviations from Plan

### Auto-resolved (Rule 3 — blocking-issue resolution)

**1. [Rule 3 — Blocking] Cherry-picked in archive-chronological order, not the plan's listed order**
- **Found during:** Task 1, before applying the install-cycle group.
- **Issue:** The plan listed cherry-pick group 2 = `dec5d59 7e72bf5` (install-cycle), then
  group 3 = `2798d6f 9d117cd` (idempotent). But in `archive/phase-7-macos`, `9d117cd` (idempotent,
  not-found branch → exit 0) was committed at 12:05 BEFORE `7e72bf5` (install-cycle) at 18:42, and
  `7e72bf5`'s diff base already contains the exit-0 idempotent not-found branch. Current main
  `uninstall.sh` still had `exit 1`. Applying 7e72bf5 first would conflict on that branch (its base
  expects exit 0, main has exit 1); applying 9d117cd afterward would conflict (it changes exit 1 →
  exit 0, but 7e72bf5 already wrote exit 0).
- **Fix:** Applied in archive-chronological order — dev-launcher (`59f803e/39aa3b6`) → idempotent
  (`2798d6f/9d117cd`) → install-cycle (`dec5d59/7e72bf5`). All four pairs cherry-picked conflict-free.
  `7e72bf5`'s modification of `uninstall_idempotent_test.lua` applied cleanly on top of the file
  `2798d6f` had already created, so the plan's "both touch it, reconcile" concern resolved itself.
- **Files modified:** tools/uninstall.sh, tools/setup.sh, tools/build.sh + their tests (as planned).
- **Commits:** 982008d, 9fbe68f, 25f05e3, d019fcc, dcfc484, b51f957.

**2. [Rule 1 — Bug] install_cycle's two staged assertions had to be flipped (they now fail truthfully)**
- **Found during:** Task 1, after the 7e72bf5 GREEN.
- **Issue:** Plan 02 staged `install_cycle_e2e_test.lua` to assert binary-absent → exit 1 + "already
  gone" warn. After 7e72bf5, that run finds the repo-local `tools/../dist/wez` fallback and exits 0
  (removing the managed block). The two staged assertions now failed (2/23) — exactly as Plan 02's
  SUMMARY flagged for this plan to flip.
- **Fix:** Flipped both to the post-7e72bf5 end-state (dist/wez fallback exit 0 + `using repo-local
  dev build` + block removed), staging a managed block so the removal is observable; updated the
  file's WAVE-CONTRACT note from "Wave 2 (pre-7e72bf5)" to "Wave 3 (post-7e72bf5)". The
  genuinely-absent idempotent exit-0 path stays covered by `uninstall_idempotent_test.lua` (isolated
  copy, no sibling dist/wez). Now 25/25.
- **Files modified:** tests/e2e/tier1/install_cycle_e2e_test.lua.
- **Commit:** b51f957 (folded into the install-cycle change-set).

### Architectural decision (Rule 4 — escalated, user-decided)

**3. [Rule 4 — Architectural] Task 2 keys-siblings fix re-shaped instead of cherry-picked**
- **Found during:** Task 2, reading the source diffs.
- **Issue:** `4c765e1` patches a fully-implemented `install_macos` (fetch → integrity-gate
  `504b0304` → `ditto -x -k` → `cp -R` → sibling-symlink loop) and needs `wezterm_macos_asset_url()`
  in `tools/lib/wezterm-release.sh`. On the Linux mainline NONE of that exists: `install_macos` is a
  D-06/D-18 design-only stub, `wezterm-release.sh` has no macOS helper, and `bootstrap_macos_test.lua`
  was never created here (it asserts ~15 absent installer symbols; the cherry-pick is a modify/delete
  conflict). Bringing the whole macOS installer forward = a major scope expansion contradicting D-18.
- **Escalation + decision:** Raised as a decision checkpoint. The user chose: do NOT bring the
  installer forward, and do NOT pure-defer with no test. Implement an OS-detect + skip-gated test —
  cross-platform parity assertion green on Linux now + a loud-SKIPPED macOS layer that fires in
  Phase 7 — plus a stub comment, and DEFER `4c765e1` + the full `bootstrap_macos_test.lua` to Phase 7
  with the macOS installer.
- **Resolution:** Implemented `keys_siblings_e2e_test.lua` (two-layer, skip-gated), the
  bootstrap-wezterm.sh stub comment, and `deferred-items.md` (D-06.6-01). See Known Deferrals.
- **Files modified/created:** tests/e2e/tier1/keys_siblings_e2e_test.lua (new),

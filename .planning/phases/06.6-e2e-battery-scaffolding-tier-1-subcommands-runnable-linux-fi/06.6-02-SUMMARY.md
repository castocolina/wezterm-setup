# Phase 06.6 Plan 02: Tier 1 Subcommand Contract Tests Summary

Deterministic Tier 1 exit-code + output-shape contract tests for every non-OSC
`wez` subcommand reachable at Wave 2 (PRD Appendix A.1), built on the Plan 01
harness and green under `make e2e` — locking the subcommand surface so the next
N runtime commits cannot silently regress it.

## What was built

**Task 1 — diagnostics + completions + no-mux scene-new (`d8eab08`)**

`tests/e2e/tier1/diagnostics_e2e_test.lua` (requires the Plan 01 harness; no
re-declared check/run_capture). Asserts per A.1 row via `run_capture_all`:
- `wez version` → exit 0 AND output contains `require("cli.spec").VERSION`
  (`0.1.0`), compared against the spec constant — NOT a hardcoded literal, so a
  version bump cannot silently break the test.
- `wez doctor` → exit 0 AND a `[PASS]`/`[FAIL]` gate token present.
- `wez keys` → exit 0 AND non-empty; `wez keys --json` → exit 0 AND
  `dkjson.decode` returns a table, with a `jq .` cross-check gated behind
  `command -v jq` (loud soft_skip when jq is absent).
- `wez completions bash` → exit 0 AND `complete -F _wez wez`;
  `wez completions zsh` → exit 0 AND `#compdef wez`.
- The no-mux `scene new` contract via a child `lua5.4 -e` calling `run_new`
  directly: zero `--pane` → exit 2 + the exact UI-SPEC copy
  `error: wez scene new requires at least one --pane (got 0)`; a bad `--layout`
  → exit 2 + `error: unknown layout 'bogus'`. NO `wezterm cli spawn/split-pane`
  runs (the validate-before-emit block returns first).
- A SUBCOMMANDS enumeration guard: every exercised non-OSC subcommand
  (version/doctor/keys/completions/scene/seed-scenes/install-state/uninstall/update)
  must be in `cli/spec.lua`'s closed allow-list, so a rename/removal fails loudly.

**Task 2 — install-cycle + scene-edge (`b9461bc`)**

`tests/e2e/tier1/install_cycle_e2e_test.lua`:
- **seed-scenes**: into a scratch `WEZTERM_SETUP_DIR` with `WEZ_SEED_SRC_DIR`
  pointed at the in-repo `scenes/` — first run exits 0 AND copies ai/dev/docker;
  re-run exits 0 AND keeps `dev.toml` byte-identical + reports `kept existing`
  (copy-if-absent).
- **install-state**: isolated via `WEZTERM_CONFIG_FILE` under a scratch `HOME`
  (the seam `config_path()` honors — never `WEZTERM_SETUP_DIR`). Fresh → exit 0 +
  exactly one managed block; explicit `--force` reinstall → exit 0 + exactly one
  block; a no-flag/no-TTY reinstall is documented non-zero today (exit 3, D-03).
- **uninstall**: driven through `tools/uninstall.sh` with a scratch `WEZ_BIN_DIR`
  + redirected `HOME`. Binary PRESENT (dummy staged at `$HOME/.local/bin/wez`,
  delegating to the real launcher) → exit 0 + managed block removed + the binary
  self-deleted (D-10). Binary ABSENT (no `wez` on PATH, none at the scratch
  bin) → exit 1 + the loud `wez binary not found … already gone` warn.
- **update**: the OFFLINE pure comparator via child `lua5.4 -e` —
  `decide_wez_update(VERSION, "", "user") == "current"` and
  `decide_wez_update(VERSION, "v9.9.9", "system") == "system-skip"` (P6-D09
  guard wins first). An OPTIONAL live `wez update` smoke gated behind
  `curl -fsS --max-time 3 https://api.github.com`: on success → exit 0 + a
  no-op/up-to-date/system-skip message; on failure → a LOUD soft_skip (never a
  silent pass, never a hang).

`tests/e2e/tier1/scene_edge_e2e_test.lua`: the three A.1 edge cases via a child
`lua5.4 -e` calling `run_launch` directly (real exit code, NO mux): unknown name
→ exit 1 + `error: no scene recipe named 'nope'`; empty dir + no name → exit 2 +
the no-name usage copy; path-traversal `../../etc/passwd` → exit 1 +
`invalid scene name` (the existing guard, T-06.6-05).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test self-deleted the real `dist/wez` dev launcher**
- **Found during:** Task 2 (first install_cycle run).
- **Issue:** The harness exports `WEZ_BIN=./dist/wez` (a RELATIVE path). The
  `wez uninstall` front door's `resolve_cli_path` reads `$WEZ_BIN` FIRST (before
  the `$HOME/.local/bin/wez` fallback), so the uninstall-present run resolved
  `cli_path = ./dist/wez` and `os.remove`'d it from the repo CWD — silently
  deleting the actual dev launcher build artifact. The live `wez update` smoke
  failed the same way (relative `./dist/wez` under a scratch-HOME prefix →
  exit 127 "not found").
- **Fix:** Run the uninstall + update subprocesses with `env -u WEZ_BIN` so the
  front door falls back to `$HOME/.local/bin/wez` (the staged dummy under the
  scratch HOME), making the D-10 self-delete observable AND harmless; and resolve
  a CWD-independent `ABS_WEZ` (relative `./dist/wez` → `<abs-repo>/dist/wez`) for
  the env-prefixed live-update run. Rebuilt the deleted artifact via
  `tools/build.sh`.
- **Files modified:** tests/e2e/tier1/install_cycle_e2e_test.lua.
- **Commit:** b9461bc.

### Source-grounded scope corrections (per plan, not new deviations)

- `scene new` has no pure spec-echo branch — the headless contract is the

- Two Wave-2 staged contracts (uninstall binary-absent exit 1; explicit-`--force`
